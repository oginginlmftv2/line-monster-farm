## 残っている本丸：243ページの薄いモンスター詳細

`monsters.html` の356リンクのうち**243本が可視300字未満のページ**を指す。
これらに広告タグは入っていない（検査20で機械的に保証）。

### 検討して却下した案

| 案 | 却下理由 |
|---|---|
| ① `monsters.html` からリンクを落とす | 効果なし。`0101.html` への被リンクを数えると、`monsters.html` を外しても**4経路残る**（モン類ページ、同血統モンスター2枚、`redirect-map.js`＝356URLが平文で並ぶJS）。AdSense審査クローラは `noindex` を尊重しない |
| ② 自動生成でテキストを増やす | `monsters-data.js` は9フィールドしかなく**全部描画済み**。埋める材料がない。定型文で嵩増しするとGoogleの「スケールされたコンテンツの不正使用」に直撃 |
| ③ 血統ページへ集約（292URLを消す） | **管理者判断で却下。**「どのユーザーがどのモンスターを見てもデータがある状態」を目指す方針のため、一時的でも逆行する |

### 採用方針：能力データにスコアを付けて全ページを厚くする

「モンスターが強いかどうかは**どの能力を使えるか**に左右される」ため、
モンスター356体を個別に書くより、能力1,095件を1回評価するほうが手数が少ない。

**設計期間の見積り：約2週間（設計＋データ入力）**

#### 実測した前提

`src/data/assist-abilities.json`（1,095件、全件 `status: verified`）

| 区分 | 件数 |
|---|---:|
| オーラ条件つき | 483 |
| モン類条件つき | 175 |
| **条件なし（全356体で共通）** | **479（43.7%）** |
| 血統条件つき | 2（ピクシー種のみ） |

1体が使える能力は約570〜600件で、**うち80〜84%が全モンスター共通**。
差分は約100〜120件しかない。

`linkStatus`: resolved 576 / unlinked **512** / ambiguous 7
→ **512件がカードに紐づいていない。**「どのカードで取るか」を出せない。

#### 差分軸の解像度（実測）

| 軸 | 組数 | 平均 | 最大重複 | 単独の組 |
|---|---:|---:|---:|---:|
| オーラ×モン類（現状） | 36 | 9.89体 | 17体 | 0 |
| **主血統×オーラ** | **169** | **2.11体** | **6体** | **66** |
| 主血統×副血統×オーラ | 323 | 1.10体 | 4体 | 298 |

オーラ×モン類だけでは**36通りにしかならず**、356ページ作っても中身は36種類になる。
**主血統を差分軸に加えることが必須**（管理者の提案。実測で妥当性を確認済み）。

#### 合意した設計方針

1. **能力の条件を2層に分ける**
   - 第1層＝適用条件（**誰が**使えるか）：オーラ／モン類／血統／距離適性／地形適性
     → 差分軸になる
   - 第2層＝発動条件（**いつ**効くか）：時間帯／天候／状態／相手依存
     → 差分軸にならないが、条件が厳しいほど**スコアを下げる**
   - 条件なし479件の内訳は 時間帯約129・地形約96・天候約38・状態約57・
     モンスター属性の取りこぼし13。**地形96件は、モンスター側に地形適性を
     持たせれば差分軸になる**

2. **血統評価値は「役割」を挟む**
   - 能力×血統を全部埋めると 1,095×34＝**37,230セル**で不可能
   - 能力→役割タグ（火力／命中／耐久／回避／ガッツ／デバフ 等6種）、
     血統→役割プロファイル、とすれば **34×6＝約200セル**で済む
   - 役割タグは既存タグ（`攻撃強化`219 / `命中強化`174 / `被ダメ軽減`67 /
     `回避`87 / `ガッツ回復`88 / `デバフ`45）でほぼ賄える

3. **散文ではなく表とスコアで出す**
   - ❌「〇〇は赤オーラの魔族であり攻撃強化を得意とします」→ 16体で同一文。スパム判定
   - ⭕ 能力名・効果・スコア・入手元カードの**表** ＋ 総合スコアの数値

4. **`ability-scores.json` は追加専用の別ファイル**
   - 既存 `assist-abilities.json` は触らず、`abilityId` を外部キーにする
   - CMS公開フローとぶつからない

#### 未決の判断

- **距離適性・地形適性をモンスター側に持たせるか。**
  `monsters-data.js` にも `monsters-editorial.json` にも構造化データが無い
  （`explanation` の自由文に「適性」81回・「中距離」74回が出るのみ）。
  入れるなら356体×7項目前後の新規入力。**スキーマ設計と同時に決めること**

- 800字ゲートの扱い。能力表を入れると292ページが**一斉に**800字を超えて
  インデックス対象へ昇格する。判定基準を可視文字数から別指標へ変える設計が要る
