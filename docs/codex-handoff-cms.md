## 0. 🔴 最初に読むこと：この引き継ぎで失われるもの

これまでは **実装役（あなた）と検証役（別セッション）が分かれていた。**
検証役は毎回リポジトリをcloneし、**実データで独立に集計し直して**受け入れ条件と突き合わせていた。

この体制で実際に見つかった誤りは、報告やdiffを読むだけでは見つからなかったものばかりである。

| 見つかった誤り | 発見方法 |
|---|---|
| 設計書が能力DBの `cardId` を必須にしていた（47%が消える） | 1,079件を実際に照合した |
| `assist-card-data.js` を「旧DB」として捨てる設計だった（唯一の凸データ源だった） | 中身を開いて52項目を確認した |
| 既存 `cards/SSR-hori.html` の見落とし（重複ページになる） | sitemapと被リンクを実物で確認した |
| 受け入れ条件の期待値 `57/91` が誤り（正しくは56） | 実装側が独立集計して矛盾を報告した |
| 凸解放は効果DBと重複していた（設計書は差別化要素と書いていた） | 3DBが揃った時点で突き合わせた |

**あなたが1人で実装と検証を兼ねると、この検出力は確実に落ちる。** 自分の実装を自分で
検算すると、同じ思い込みが両方に入るためである。したがって次を必ず守ること。

### 守ること

1. **完了条件の数値は、実装に使ったコードとは別の経路で検算する。**
   生成スクリプトの出力をそのまま完了条件の証拠にしない。使い捨ての検算スクリプトを
   別に書き、集計方法を変えて（別のループ、別の集約順、元ファイルから直接）確かめる
2. **`scripts/verify.js` に検査を足したら、必ず壊して落ちることを確認する。**
   データを意図的に壊したコピーを `/tmp` に作り、FAIL が出ることを確認してから完了とする。
   通ることの確認だけでは、検査が入った証明にならない
3. **期待値に合わせてデータや判定を歪めない。** 矛盾を見つけたら AGENTS.md 第8章に従って
   停止し、管理者に報告する。過去に一度これで正しく止まり、指示側の誤りが訂正された
4. **管理者への報告に「確認しました」と書くときは、何をどう測ったかを併記する。**
   件数だけでなく、集計方法と入力のhashを残す

## 2. 次のタスク：P12-8 アシストCMS基盤（test環境）

ブランチ `feat/p12-8-assist-cms`、本番影響 ⚪（test環境のみ。本番deploymentを変更しない）。

### 方針（`docs/assist-card-cms-progress.md` 第7章が正）

**スプレッドシートはモンスターCMSと同居させる。公開経路だけ分ける。**

```
同じスプレッドシートにシートを追加
  cards / assist_effects / abilities / capture_queue / publish_log

公開経路は分離
  モンスター: cms/publish        → 既存Workflow・既存許可リスト
  アシスト  : cms/assist-publish → 新Workflow・カード用の別許可リスト
```

### 🔴 絶対にやってはいけないこと

**`scripts/verify-cms-source.js` の許可リストにカード用ファイルを追加しない。**

```js
TEXT_SOURCE_FILES = monsters-data.js / cms-id-predictions.json / monsters-editorial.json
IMAGE_PATH        = monster/<4桁>.(jpg|png|webp)
```

これはモンスターCMSの公開ゲートで、**狭いことが価値**である。広げるとモンスター側の
守備範囲まで緩む。アシスト用は**別の許可リストを別Workflowに持たせる。**

### 🔴 `sitemap.xml` の競合

`sitemap.xml` は両方の公開経路が書き換える生成物である。同時に走ると片方のURLが消える。

- GitHub Actions に **concurrency group** を設定して2つの公開Workflowを直列化する
- どちらの経路も、差分を当てるのではなく**必ず全データからsitemapを作り直す**

### `build.js` の注意点

sitemapの生成URL判定と手書き定数は P12-7b で次のように変わっている。**両方を意識すること。**

```js
generatedUrlPattern = /...\/(?:monsters\/(?:...)|cards\/[^/]+\.html)<\/loc>/;
if (existingBlocks.length !== 23) { throw ... }
```

日記・ガイド記事を1本増やしたら、この **23 を手で増やす**必要がある。

### 秘密情報

**このリポジトリは公開されている。** 秘密値を1文字でも書いたら誰でも読める。

| 値 | 置き場所 |
|---|---|
| GitHubトークン | GAS の Script Properties と GitHub Secrets のみ |
| スプレッドシートID / DriveフォルダID | 同上 |
| 許可メールアドレス | シートのみ。コード・JSON・HTMLに出さない |

- アシスト用tokenを作る場合も、本番 `CMS_PUBLISH_TOKEN` と共有しない
- 誤ってコミットしたら即座に失効させて作り直す。git履歴からは消えない

## 3. 積み上がっている不変条件を壊さないこと

`scripts/verify.js` は現在51項目。**既存の検査項目の挙動を変えない。追加だけ行う。**

特に次は、これまでの作業で意図的に守ってきたものである。

| 守るもの | 理由 |
|---|---|
| 効果DBの `name`+`description` 重複81件 | 凸で同じ効果が再度上乗せされるゲーム仕様。消すとデータが失われる |
| 能力DBの `unlinked` 512件 | 現行カードに無い名前。母集団を広げたとき拾い直す唯一の手がかり |
| 能力DBの `duplicate-candidate` 44件 | 入力ミスの可能性が高いが、原本確認前に消すと復元できない |
| フレリアMR/SSRが共有する画像4枚 | 同一キャラの別レアリティ。重複検査で弾かないこと |
| `sapo-card-map.json` の `candidate` 3件 | 同名別レアリティ。自動確定しない |
| 未参照の能力画像11枚 | 未使用か割当漏れか判断できない。削除しない |
| `cards/SSR-hori.html` | 既存の被リンク・インデックス資産。転送ページとして残す |
| noindexページに広告を入れない | verify.js がFAILにする |

**検査に固定件数（888、1079など）を埋め込まないこと。** CMSでデータが増減すると
毎回FAILになる。構造的な不変条件だけを検査する。

## 8. 毎回の作業手順



- `main` に直接コミットしない
