# CMS統合 計画

作成: 2026-08-25
状態: 方針確定・具体設計は P12-10 で行う

## 1. 決めたこと

モンスターCMSとアシストCMSを、**1つのApps Scriptプロジェクト・1つのWebアプリ**へ統合する。
タブ切り替えで両方を扱い、UI・共通部品・認証・tokenを一本化する。

**ただし公開ゲートは統合しない。** 編集画面は1つ、公開経路は2つのままとする。

## 2. 何を統合し、何を統合しないか

| 統合する | 理由 |
|---|---|
| Apps Scriptプロジェクト | deployment・権限承認・保守が1組で済む |
| WebアプリURL / deployment | 運用者が1画面で完結する |
| 認証・`members`・許可メール | 名簿が1つになり、追加・削除の漏れが消える |
| Script Properties | token・シートID・フォルダIDの管理が1組 |
| GitHubトークン | 1本で済む。P11-8の最小権限化も1回で完了する |
| UI枠・スタイル・共通部品 | 現在 約4,140行。重複を削れる |
| スプレッドシート | すでに同居方針。変更なし |

| 統合しない | 理由 |
|---|---|
| 公開ブランチ（`cms/publish` / `cms/assist-publish`） | 片方の失敗がもう片方を巻き込まない |
| 許可リスト（`verify-cms-source.js` の対象） | ゲートの価値は狭さにある |
| ビルド検査の単位 | 変更範囲が不明確だと差し戻し判断ができない |

### 🔴 なぜ許可リストを1本にしないか

現在のゲートは、モンスター公開のコミットが触れてよいファイルを3つ＋画像パスに限定している。
カード用ファイルを同じリストに足すと、モンスター側の守備範囲まで広がる。

カード編集中の誤操作でモンスターDBを巻き込んだ差分が生まれても、ゲートが通してしまう。
**mainへのマージ＝即公開**なので、これは実害になる。

UIが1つでも、公開時に「今回変更したドメイン」でブランチを出し分ければ、
ゲートは狭いまま、運用者から見た画面は1つにできる。

## 3. リスク

| リスク | 対処 |
|---|---|
| 稼働中のモンスターCMSに手を入れる。壊すと唯一動いている公開経路が止まる | test環境で完成させてから本番deploymentを切り替える。切替は独立タスク |
| `_cms/gas` は監査の正で、C10トークン検査が必須2ファイル前提 | 構成変更に合わせて検査を作り直す。**検査を弱めない** |
| GASの6分実行制限 | 公開処理はドメイン別に分けたまま実行する。全件同時publishを作らない |
| 誤操作（カード編集中にモンスター公開を押す） | 公開ボタンをドメイン別に分ける。UI設計の必須要件 |
| deploymentが1つになりロールバック単位が粗くなる | 変更を小さく刻む |

### GitHub権限の前提（2026-08-25 確定）

リポジトリのオーナーは別の個人アカウントであり、作業者はコラボレーター（write）である。
**個人アカウントのリポジトリには「オーナー」と「コラボレーター」の2段階しか無く、
admin をコラボレーターへ付与できない。** この前提は変わらない。

| 操作 | 可否 |
|---|---|
| push / PRのマージ / ブランチ作成 | ○ |
| GitHub Actions の実行と結果確認 | ○ |
| Secrets and variables の閲覧・編集 | ○ |
| Settings → Actions → General（Workflow permissions） | **×** |
| Rulesets / Branch protection | **×** |
| Pages の設定 / 可視性 / 移管 / 削除 | **×** |

### この前提が計画に与える影響

- **P11-7 は実施不可。** test Ruleset と Workflow permissions の変更ができない
- **P11-9 は不要。** main の Ruleset を有効化すると、mainへ直接pushするCMSが止まる。
  公開ゲートは `scripts/verify-cms-source.js` としてWorkflow内に実装済みで、
  ブランチ保護が無くても機能する
- **旧「統合CMSの公開PR経路test」は実施不可。** GitHub Actions によるPR作成に
  admin 権限の設定が必要なため、統合の必須要件から外す
- **P11-8（token最小権限化）は実施可能。** ただしCMS統合でtokenが1本になるため、
  Phase E（P12-12）と同時に1回で行う

**結論: CMS統合（Phase C〜E）は admin 権限なしで完結する。**

### 復旧の前提

リポジトリは公開で、独自ドメイン `line-monster-farm-tetteikouryaku.com` を CNAME で配信している。
**完全な履歴つきローカルクローンを常に最新に保つこと。**
配信基盤に問題が生じた場合の復旧は、クローンとドメインの再設定によって行う。

- **執筆12件**：あと数十字で index対象に昇格するカード
  （キャトル あと4字 / ピーシィ(黄) あと20字 / ディアナ あと30字 / キング あと37字 ほか）
- **Search Console の週次観測**：sitemapフィルタの登録済み件数と、
  「クロール済み - インデックス未登録」の推移

**AdSense再申請は登録済みが伸びてから。** 現在 sitemapフィルタで39件、
「検出 - インデックス未登録」が40件滞留している。
