# 専用技のクラウド取り込み 設計

専用技（モンスター詳細の技タブ）のスクショ読み取りを、手元のセッションから
**クラウドセッション（claude.ai/code）**へ移す。手元のトークンを使わず、他の作業とも並行できるようにする。

状態：7章は推奨どおりで決定（2026-10-15）。8章の1〜3（`unique_pack.py`・検査スクリプト・スキル `unique-skill-cloud`）を実装済み。ミリム・リゾートの束を受け箱へ送り済み。

## 1. いまの問題（2026-10-15 ミリム・リゾートで実測）

| 項目 | 実測 |
|---|---|
| 1体ぶんの枚数 | 21枚（技5件）。同じ技の画面を2回撮った重複が6枚 |
| 1枚の大きさ | 828×1836。読む必要があるのは右の技欄と能力詳細の枠だけで、画面の約3割 |
| 手作業 | オーラ色の拡大確認、既存技能力との文面照合、技IDの引き当て、アイコンの切り抜き |

トークンの大半は「画面全体を1枚ずつモデルに見せる」ことで使っている。
照合・TSV化・アイコンは毎回同じ手順なので、モデルが考える必要はない。

## 2. 全体の流れ

```text
［手元のMac］
  LMFShot（モード unique）で撮る → ~/Pictures/lmf-capture/unique-skills/
  unique-pack <モンスター名>     ← 新規スクリプト
    ・重複画像を捨てる（同じ技の画面）
    ・技欄・能力詳細・技グリッドだけ切り抜いて縮小
    ・オーラ丸を拡大した小画像も添える
    ・inbox ブランチへ push
            │
［クラウドセッション］
  入力者が claude.ai/code で「受け箱の専用技を取り込んで」と起動（7章で定期実行も検討）
    ・切り抜き画像を読む（モデルはここだけ）
    ・照合・TSV追記・取り込み・アイコン・build・verify はスクリプト
    ・読み取り表を本文に書いた PR を作る
            │
［入力者］
  PR の表を見てマージ（＝確認）。迷った点は PR に質問として出る
```

**モデルが見るのは「切り抜いた文字の部分」だけ**にし、それ以外はすべてスクリプトにする、というのが設計の芯。

## 3. 手元：`unique_pack.py`（tools/skill-autocapture/unique_pack.py）

ミリム・リゾートの21枚で試した結果：重複5枚を除外し、技5件の間合いはすべて登録内容と一致した。束は2.1MB（元26MB）、モデルに見せる画素は全面の **10.8%**。
タップの光が残った同じ詳細画面（連撃：破壊の暴君）は、重複として除けずに2枚とも残る。

入力：`unique-skills/` の未処理画像と、モンスター名（引数）。

1. **名前を先に確定する。**`monster-ids.json` に無い名前なら止まる。血統・ID はここで引く
2. **重複を捨てる。**技欄の切り抜きの画素差が小さい連続画像は1枚にまとめる
3. **画面の種類を分ける**（色と位置で判定。モデルは使わない）
   - 技タブ（モンスター詳細）／能力詳細／技能力詳細（解放条件つき）
4. **切り抜き**（座標は 828px 幅を基準に比率で持つ。今回の画面で実測した値）
   - 技タブ → 技欄（技名〜技能力）と技グリッド。グリッドは選択枠の位置＝間合いの判定とアイコン用
   - 能力詳細・技能力詳細 → ダイアログの枠だけ
   - オーラ丸 → 3倍に拡大した小画像（白／黒の取り違え対策）
5. **束ねる。**`inbox/unique/<日時>-<モンスターID>/` に切り抜き画像と `manifest.json`
   （モンスター名・ID・血統・元画像名・画面種別・選択中のマス）を置く
6. **送る。**孤立ブランチ `inbox/unique-skills` へ commit・push。終わったら元画像を
   `unique-skills/done/<日付>/` へ移す

孤立ブランチにするのは、`main` とサイト（GitHub Pages）にスクショを載せないため。
取り込みが済んだ束は、クラウド側が同じブランチから消す。

## 4. クラウド：読み取りと取り込み

起動時の指示は1文で済むよう、手順はスキル `unique-skill-cloud`（`.claude/skills/unique-skill-cloud/SKILL.md`）に書いた。
技アイコンは `skill_icon.py add-pack <束> <読取.json>` で置く（取り込み後の技DBから技IDを引く）。

1. `inbox/unique-skills` から未処理の束を1つ取る（1セッション1体）
2. **読み取り（モデル）**：切り抜き画像を読み、技ごとに JSON を出す
   - 技名・ランク・オーラ・技種・ガッツ・移動・4評価・技能力名・解放条件
   - 能力詳細の本文
   - **読めない値は `null`。推測で埋めない**（従来どおり）
3. **検査（スクリプト `scripts/check-unique-skill-payload.js`。実装済み。読取JSONの形はファイル冒頭）**
   - ミリム・リゾートの読取で `--apply` した結果は、手作業で登録した PR #297 の10行と完全に一致した
   - 終了コード 0＝追記できる／1＝FAIL（読取を直す）／2＝STOP（入力者に聞く）。`--report` で PR 本文用の表を出す
   - 間合いは manifest の「選択中のマス」の列から決める（モデルに読ませない）
   - 技能力名が登録済みなら文面を突き合わせる。**一致**→参照のみ／**不一致**→止まる（下記）
   - 同名の共通技が他血統にある → PR に注記（今回のパンチ・キック）
   - 評価の文字・★の数・オーラ色が決まった値か
4. **TSV 追記 → `import-skills-tsv.js` → `skill_icon.py add`（グリッドの切り抜きから）→
   `build.js` → `test-skill-build.js` → `verify.js`**
5. **PR を作る。**本文に読み取り表・新規技能力・注記を、手元セッションと同じ形で書く

### 止まる条件（PR を draft にして本文に質問を書く）

従来スキルの「自分で決めない」ものは、クラウドでも決めない。

- 登録済みの技能力と名前が同じで文面が違う（版の更新か、同名別物か）
- オーラ色が白か黒か決めきれない
- 解放条件がありそうなのに読めない
- 専用技ではなく共通技の可能性がある（「登録済みの共通技名＋接尾辞」の形）
- `verify.js` が FAIL

入力者は PR に返事を書き、同じクラウドセッションへ続きを頼む。

## 5. 確認の仕方の変更

従来は「1技ごとに表を返して確認 → 書く」だった。クラウドでは**PR のマージが確認**になる。

- 束ねる時点でモンスター名を入力者が指定しているので、取り違えは名前ではなく技単位でしか起きない
- PR 本文の表は、技ごとに元の切り抜き画像を並べる（見比べやすくする）
- マージ前の修正は PR へのコメントで頼む

## 6. 費用の考え方

- クラウドセッションはクラウド用クレジットから引かれる。**クレジットの上限は claude.ai 側にあり、
  この仕組みでは100ドルで止める制御を持てない。**使用量は claude.ai の使用量画面で見る
- 1体あたりの読み取り量は、全面21枚→切り抜き十数枚（重複除去後）に減る見込み。
  最初の3体で実際の消費を記録し、ここへ書き足す
- 読み取りはモデルを Sonnet にできるか、最初の数体で精度を比べてから決める（オーラ色・評価の `+` が要注意）

## 8. 実装の順番

1. `unique-pack.sh`（切り抜き・重複除去・束ね）だけ先に作る。**手元での取り込みもこれで軽くなる**
2. `check-unique-skill-payload.js` と読み取り JSON の形式
3. スキル `unique-skill-cloud` とクラウドでの試行（ミリム・リゾートの束で、今回の登録内容と一致するか確かめる）
4. 費用の実測を6章へ追記
