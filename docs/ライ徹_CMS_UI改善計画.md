# ライ徹 CMS UI改善計画

作成: 2026-08-30
対象: `oginginlmftv2/line-monster-farm` の `_cms/gas/`（GAS Web App の管理画面）
着手時期: **ガチャデータ実装（G1〜G5）の完了後**
前提となる計画書: `ライ徹_ガチャデータ実装計画.md` / `ライ徹_CMS設計書.md`

---

## 0. 目的

CMSは動くようになったが、**使い続けられる画面になっていない。**
余白の潰れ、はみ出し、戻れない画面、英単語だらけのラベル——
どれも1つずつは小さいが、合計すると1件あたりの入力時間を確実に押し上げている。

運用工数の削減がプロジェクトの主目的である以上、**画面の使いにくさは技術的負債と同じ**。

**ガチャCMS（G3）が入って画面が3ドメインになった状態で、まとめて直す。**
ガチャ画面の崩れ・使いにくさもこの計画に含める（3章）。

---

## 1. 原則

1. **見た目の変更のみ。機能を壊さない。**
   バリデーション・API・シート書き込みのロジックには原則触れない。
2. **APIでやり取りする値は英語のまま。日本語にするのは画面表示だけ。**
   `linkStatus` の `resolved` を日本語にした瞬間に `verify.js` と3DB検証が落ちる。
   `<option value>` は絶対に変えない（5章の対訳表）。
3. **確認工数を増やさない。**
   本番ブックのコピーは作らない。スプレッドシートは版履歴で戻せる。
   動作テストは「その画面で1回操作する」程度に留める。
4. **GAS操作はすべてユーザーが行う。** Codexにはコードを書かせるだけ。
5. **3PRで終える。** 単純なUI変更なので、確認は各PR1回・軽く済ませる。

## 2. 調査結果 — なぜこうなっているか（2026-08-30 実地確認）

**要望の大半は個別のバグではなく、CSSの構造的な問題1つから来ている。**
ここを直さずに個別対応すると、同じ症状が別の場所で再発する。

### 2-1. 🔴 `ui_common.html` にCSSが2系統、そのまま連結されている

モンスター画面時代のCSS（`--bg:#f6f7f9` / 青系 / ブレークポイント860px）と、
アシスト画面時代のCSS（`--cream:#f8f2e7` / 茶系 / ブレークポイント760px）が
**1つの `<style>` に上下に貼られている。** 後勝ちで次が衝突している。

| セレクタ | 前半（モンスター） | 後半（アシスト） | 実際に効く値 | 症状 |
|---|---|---|---|---|
| `:root` | 青系パレット | 茶系パレット | 茶系 | モンスター画面が意図しない配色 |
| `input,select,textarea` | `width:100%`（type限定） | **`width:100%`（type無制限）** | 無制限 | **ラジオボタンが幅100%になり中央に見える** |
| `.filters` | `display:flex;flex-wrap` | **`display:grid; 1fr 110px`** | grid 2列 | **「ID順」が110px枠に150px指定ではみ出す** |
| `.panel` | `padding:12px` | **padding指定なし** | 0 | **要素の左右余白が潰れる** |
| `@media` | `max-width:860px` | `max-width:760px` | 両方 | **760〜860pxで表示が壊れる帯がある** |
| `.mobile-back` | `display:none` | `display:none` | none | **PCで「戻る」が一切出ない** |

**要望の「余白が潰れている」「ラジオが真ん中」「ID順がはみ出る」「PCで戻れない」は、
すべてこの表の1行ずつに対応している。**

### 2-2. 使われているのに定義が存在しないクラス

| クラス | 使用箇所 | 定義 | 症状 |
|---|---|---|---|
| `.domain-tools` | `ui_monster.html` / `ui_assist.html` の最上部 | **なし** | **タブ直下のボタン行に余白もgapも無い**（要望の筆頭） |
| `.asstField` | アシストのフォーム全域（数十箇所） | **なし** | ラベルと入力の間隔なし |
| `.asstField.wide` | 説明・タグなど | **なし**（`.field.wide` のみ定義） | **全幅にしたい欄が2カラムに潰れている** |

### 2-3. その他

- `.domain-panel > main` に `max-width:1440px;margin:auto` → **アシストだけ横幅が伸びない**（要望どおり）。モンスター側の `.wrap` に max-width は無い。
- `#message.show` の固定表示CSSがあるが、実際のidは `asst_cardMessage` などで**一致せず死んでいる**。
- `h2` / `h3` にスタイル指定がなく、ブラウザ既定の大きな上下マージンが出る。
- 監査サマリーの `.grid`（2列固定）に SHA-256 のような長文字列が入り、`overflow-wrap` 未指定で**枠を突き破る**。スマホの横スクロールはこれが主因。
- `ui_publish.html` はボタン4つが `.panel` 直下に連続配置で、**gapが一切ない**。

## 5. 各段階の詳細

### U0 — 解説の改行・箇条書きの描画修正（サイト側）

#### 5-0-A. 調査結果 — 原因は2つとも**ページ側**（2026-08-30 実地確認）

**① 1行空けが反映されない**

`build.js` の `formatExplanation()`（127行目）が、**空行を読み飛ばして捨てている。**

```js
if (!line.trim()) { index++; continue; }   // ← 空行がここで消える
…
return blocks.join('');                    // ← 区切りなしで連結
```

さらに `style.css` の1行目に **`* { margin:0; padding:0 }`** があり、
生成された `<p>` `<ul>` の**マージンがすべて殺されている**。
つまり現状は「空行が消える」だけでなく、**段落の間隔そのものが0**。
`.expl-body` の `white-space:pre-wrap` は `<p>` 化以前の名残で、現在は何の働きもしていない。

**② 中黒が左にはみ出る → ページ側の問題。原稿は正しい。**

`・` で始まる行が2行以上続くと `<ul><li>` に変換される（`build.js` 139-146行）。
`ul` の既定 `padding-inline-start:40px` が **`*{padding:0}` で潰されている**ため、
`list-style:disc outside` のマーカーが**コンテンツ枠の外（左）へ出る。**

> ご指示は「ページ側であれば無視」でしたが、**CSS 2行で直り、U0 で同時に触る箇所です。**
> 直さない理由がないので、含める前提で書いています。外す場合はこの項だけ削除してください。

#### 5-0-B. 🔴 既存データの一括置換は「不要」

96件の解説を調べた結果：

```
解説あり            96件
複数行              96件
空行を含む          59件（うち空行の直後が「・」= 76箇所）
中黒2行以上         81件
```

**空行はすでに正しく入っている。** 書き手は最初から「1行空けてブロックを分ける」書き方をしており、
`build.js` がそれを捨てているだけ。

したがって——

- **シートの一括置換は行わない**
- **`<br>` への置換もしない**（`escapeHtml` を通るので `<br>` はそのまま文字として表示される。
  入れてはいけない）
- 直すのは描画側だけ。**原稿は1文字も触らない**

#### 5-0-C. 実装

**1. `build.js` — 空行を「間隔あり」の印として次のブロックへ渡す**

```js
// 空行を読み飛ばすとき、フラグだけ立てる
if (!line.trim()) { gap = true; index++; continue; }
// ブロック生成時に付与
blocks.push(`<ul${gap ? ' class="gap"' : ''}>…</ul>`);
blocks.push(`<p${gap ? ' class="gap"' : ''}>…</p>`);
gap = false;
```

- **連続する空行は1つ分として扱う**（2行空けても間隔は変わらない）
- 先頭の空行は無視する（`gap` を立てても最初のブロックには付けない）
- 出力の変化は **class属性が増えるだけ**。テキストは1文字も変わらない

**2. CSS — `style.css` に `.expl-body` の段落規則を足す**

```css
.expl-body p  { margin:0 0 10px; }
.expl-body ul { margin:0 0 10px; padding-left:1.4em; }   /* ← 中黒はみ出しの修正 */
.expl-body li { margin:0 0 4px; }
.expl-body .gap { margin-top:22px; }                     /* ← 1行空けの再現 */
.expl-body > :last-child { margin-bottom:0; }
```

`monster-detail.css` の `.expl-body { white-space:pre-wrap; }` は**削除**する。

**3. ガチャ解説も同じ見た目にする**

`formatExplanation()` の出力は現在3箇所で使われている。

| 箇所 | 現状 | 対応 |
|---|---|---|
| モンスター詳細（1024行） | `<div class="expl-body">` で包まれている | そのまま |
| ガチャ詳細（410行） | **素で出ている** | `<div class="expl-body">` で包む |
| トップのピックアップ（261行） | **素で出ている** | 同上 |

#### 5-0-D. アシストカードの解説は**対象外**（確認済み・2026-08-30）

カード詳細は `formatExplanation()` を通していない。**別経路で描画されている。**

```js
// scripts/build-assist-pages.js 129行
<div class="explanation-body">${escapeHtml(card.explanation)}</div>
```

```css
/* style.css 450行 */
.explanation-body { white-space: pre-wrap; }
```

**生テキストを `pre-wrap` で出しているだけなので、改行も空行もそのまま反映されている。**
中黒も `<ul>` に変換されず文字のまま出るため、はみ出しも起きない。

| | モンスター／ガチャ | アシストカード |
|---|---|---|
| 描画 | `<p>` / `<ul>` へ変換 | 生テキスト＋`pre-wrap` |
| 改行 | **潰れる（U0で修正）** | **反映済み** |
| 空行 | **消える（U0で修正）** | **反映済み** |
| 中黒 | `<ul>` のマーカーが枠外へ（U0で修正） | 文字のまま。問題なし |

実データ（85件）でも `・` 始まりが84件・空行を含むものが2件で、いずれも現状で正しく出ている。

**→ U0でカード側のファイルは1つも触らない。**

⚠ ただし U0 の後、**モンスターとカードで解説の見た目が分かれる**
（モンスターは `•` のリスト、カードは `・` の素テキスト）。
統一するかどうかは**保留**とする。統一する場合はカード側の可視文字数の数え方
（`stripTags(card.explanation).length`）と表示文字数がずれるため、
インデックス判定への影響を先に確認する必要がある。**U0では踏み込まない。**

#### 5-0-E. 影響範囲の確認

- **インデックス判定に影響しない。** `visibleChars()` は `.replace(/<[^>]+>/g,'')` で
  タグを除去してから数えるので、class属性が増えても可視文字数は変わらない
- **既存93ページの見た目は変わる**（段落間隔が付き、中黒が枠内に収まる）。これは意図した改善
- ⚠ `git diff` は全モンスターページに及ぶ。**差分の中身は class 属性と空白だけ**であることを
  Codexに確認・報告させる

#### 完了条件

- `node build.js && node scripts/verify.js` が **FAIL 0 / WARN 0**
- 空行を含む解説（例：`1150` / `1450` / `1651` / `1751`）で、**空行の位置に間隔が出る**
- 中黒の箇条書きが**枠内に収まる**（スマホ375pxでも）
- `src/data/monsters-editorial.json` の差分が **0行**（原稿を触っていないこと）

対訳表は `ui_common.html` に1箇所だけ置く。


フィールド名そのものも同様に和名を添える。

|---|---|

| 状態（status） | status |
| 処置（disposition） | disposition |

| 外部指紋（externalFingerprint） | externalFingerprint |

⚠ `candidateKey` `externalSha` `NFKC` など、**和訳するとかえって分からなくなる技術値は
英語のまま**にする。無理に全部訳さない。

#### 5-2-D. 能力一覧での「状態」インライン切替

`asstRenderAbilities()` の各行に `<select>` を1つ足す。

```
[能力名]  下書き（draft） ▼   [編集]
 abilityId / 入手元
```

- 行の背景色でも状態を示す（`draft` は薄い黄）。**色だけに頼らず文字も出す**
- 並びは現状維持（`sortOrder` 順）

**🔴 保存はサーバ側を変えない方法を採る。**
`api_asstSaveAbility` は `{ability, version}` の全項目更新で、一覧側は `version` を持っていない。

```
選択変更
  → api_asstGetAbility(abilityId)   … 最新の全項目と version を取得
  → status だけ差し替える
  → api_asstSaveAbility({ability, version})
  → 成功したらその行だけ再描画
```

**新しいAPIを作らない。** 既存の検証・排他制御・updatedBy記録がそのまま効く。
往復2回になるが、編集画面へ入る現状より確実に速い。

- 通信中はその行の `<select>` のみ `disabled`（全ボタンを止める既存の `setBusy` は使わない）
- 失敗したら選択を元に戻し、`show(message,true)` でエラーを出す

- 絞り込み3種が効く。能力→編集→戻る、で能力一覧に戻れる
- 1件だけ状態を切り替え、シートの `status` と `version` が更新される。**他の列が無傷**
- `value=` の件数が変更前後で一致（Codexが grep して報告）

### U3 — 外部能力DB監査ページ

差分が最も大きい。**この段階だけは、着手前に画面構成を文章で確定してから始める。**

#### 5-3-A. 監査サマリーを折りたたむ

```html
<details id="asst_auditSummary"><summary>監査サマリー（監査成功 / 問題なし）</summary>
```

- **デフォルトは閉じる**（その下の候補一覧を優先する）
- ただし `auditStatus=FAIL` または `safetyVerdict=BLOCKED` のときは **強制的に開く**
- 開閉状態は `ASST.audit.foldOpen` と同じ要領で保持し、再監査後も維持する
- `summary` に**要約1行**（監査状態／安全性判定／総候補数）を出す

#### 5-3-B. 候補一覧をタブ切替にする

現在は `<details>` を分類ごとに縦に並べている。これを**タブ**に変える。

```
[カード対応候補 (12)] [未紐付け候補 (3)] [ID再利用疑い (0)] [既存内容差分 (5)] [その他 (2)]
```

- タブは `ASST_AUDIT_CATEGORIES` の順。**7分類は多いので、後半3つ
  （表記違い／重複内容一致／外部欠落観測）は「その他」に束ねて5タブ**にする
- 件数は**対応方針名の右に括弧書き**（要望どおり）。
  括弧内は `data.counts` の**全体件数**を出し、タブ内の見出しに「このページ N件」を添える
- 件数0のタブは `disabled` にして残す（消すと「無い」のか「見落とした」のか分からない）
- 選択中タブは `ASST.audit.tab` に保持。ページ送り・再監査をまたいで維持する
- 「処置済みを表示」チェックはタブの外（全タブ共通）に置く

⚠ **APIが返す候補の優先順は変えない。** タブは表示の絞り込みだけで、
`asstOpenAuditDetail(index)` に渡す index は**元配列の添字のまま**にすること。
ここを取り違えると**別の候補を編集する事故**になる。

#### 5-3-C. ページ送りに「最初へ」「最後へ」

```
[« 最初へ] [‹ 前へ]  3 / 12 ページ ・ 総候補数 574  [次へ ›] [最後へ »]
```

- 既存の `asstLoadExternalAudit(page,false)` をそのまま呼ぶ（新規APIなし）
- 1ページ目では「最初へ」「前へ」を `disabled`、最終ページでは逆
- スマホでは2段に折り返す（`flex-wrap:wrap`）

#### 5-3-D. スマホの横スクロールを止める（監査ページ・候補詳細の両方）

原因は 2-3節のとおり `.grid` 2列固定＋長文字列。

```css
@media (max-width:860px){ #asst_editor .grid{ grid-template-columns:1fr; } }
.readonly{ overflow-wrap:anywhere; word-break:break-all; }
```

- SHA-256（64文字）・fingerprint は `word-break:break-all` で折り返す
- ⚠ **折り返すと縦に伸びる。** 監査サマリーが閉じている（5-3-A）ことが前提で成立する
- 折り返した `.readonly` に `max-height:8em; overflow:auto` を入れ、
  1項目が画面を占領しないようにする
- **`overflow-x:hidden` で誤魔化さない。** 中身を折り返して解決する

#### 5-3-E. 候補詳細から戻る

現状 `asst_btnBackAuditDetail` は `class="mobile-back"` で **PCでは非表示**。

1. 「処置を保存」の隣（左）に **「戻る」ボタン**を追加
2. **戻り先は「見ていたページ番号のその一覧」。**
   `asstReturnFromAuditDetail()` は `detailIndex=null` にして再描画するだけなので、
   `ASST.audit.response` が保持されていれば**ページ番号は維持される**。
   ⚠ `ASST.audit.tab`（5-3-B）も併せて復元すること
3. 上部の `mobile-back` は**削除し、下部に一本化する**（両方出ると押し間違える）

#### 完了条件

- 監査ページを開き、サマリーが閉じた状態で候補一覧が最初に見える
- タブを切り替え、詳細を開き、戻って**同じページ・同じタブ**に戻る
- 375px幅で監査ページ・詳細ページとも**横スクロールが発生しない**
- 処置保存を1件だけ実行し、従来どおり動く
