# モンスター基礎データ（素質・特徴・適性）の設計

最終更新: 2026-09-17（P15-4 1-a）

モンスター詳細ページを1体ごとに固有の内容で厚くするため、ゲームの「モンスター詳細」画面
右上3タブ（基礎・特徴・適性）の値をDBに持ち、`build.js` が「基礎データ」セクションとして描画する。
背景は `docs/adsense-indexing-handoff.md`（主血統×オーラでは最大6体が同一内容になる問題）。

| 物 | 場所 | 役割 |
|---|---|---|
| 生データ | `src/data/monster-basics.json` | 画面に写る値だけ。**評価値は保存しない** |
| 転記元 | `src/data/_source/monster-basics-<血統slug>.tsv` | スクショから転記。テンプレは `monster-basics-template.tsv` |
| 取り込み | `scripts/import-monster-basics-tsv.js` | TSV全部→JSONをまるごと書き直す |
| 式とスキーマ | `src/lib/monster-basics.js` | **点数表・加重・閾値・列挙の唯一の置き場** |
| テスト | `scripts/test-monster-basics.js` | 較正6体の期待値、検証の破壊ケース、TSV取り込み |
| 描画 | `build.js` `renderMonsterBasics` | 詳細ページの「基礎データ」（`docs/build-spec.md` 5-11） |
| 検査 | `scripts/verify.js` 21 | スキーマ、TSVとの一致、較正値、ページとの整合、CMS境界 |
| 入力手順 | `.claude/skills/monster-basics-capture/SKILL.md` | スクショ→TSV→取り込み→ビルド |

管理区分は**リポジトリ管理**（技DBと同じ）。CMSの対象外で、CMS公開Workflowはこのファイルを
触らない（`scripts/verify-cms-source.js` の対象集合に入れていないことを検査21が保証する）。
CMS化するときはこのJSONをシートへ流し込む。

## 1. 画面と列

| タブ | 読む項目 | 列 | 値 |
|---|---|---|---|
| 基礎 | 「素質」列（右端）6行 | `talent.life/power/wisdom/accuracy/evasion/defense` | 符号付き整数％ |
| 特徴 | ガッツ回復力／移動速度 | `gutsRecovery` `moveSpeed` | `G`〜`S` |
| 特徴 | 成長タイプ／ヨイワル／サイズ | `growthType` `goodEvil` `size` | 列挙（画面で見た値だけ足す） |
| 適性 | 地形適性5項目 | `terrain.砂漠/森林/海岸/雪山/火山` | `G`〜`S` |
| 適性 | 間合い適性4項目 | `range.far/mid/near/zero` | `G`〜`S` |

読まないもの：基礎ステータスの数値とその左のランク文字（個体値）、血統アイコン、
忠誠度・人気度・絆レベル・★（個体値）、才能（種族固有だが不要と判断）。

適性のランクに `+` は無い。地形名は `src/data/assist-aptitudes.json` の語彙と同じ。

### スキーマ（`monster-basics.json`）

```jsonc
{
  "schemaVersion": 1,
  "monsters": [                       // ID昇順の配列（オブジェクトだと数値風キーで順序が崩れる）
    {
      "id": "3151", "name": "メレンゲ",
      "talent":  { "life": 0, "power": -5, "wisdom": 10, "accuracy": 20, "evasion": 5, "defense": -5 },
      "gutsRecovery": "A", "moveSpeed": "B",
      "growthType": "ふつう", "goodEvil": "ややヨイ", "size": "小さい",
      "terrain": { "砂漠": "C", "森林": "F", "海岸": "D", "雪山": "B", "火山": "B" },
      "range":   { "far": "B", "mid": "D", "near": "B", "zero": "D" },
      "capturedAt": "2026-09-17"
    }
  ]
}
```

- `talent`・`terrain`・`range` はグループ単位で「全部ある」か「無い」か。特徴の5項目は個別に任意
- 部分的に入った体も許す（撮れた枚から入れられる）。ページはあるブロックだけ出す

## 2. 評価式（地形適性評価・間合い適性評価）

### 前提：ゲーム仕様

- 育成開始時に適性がランダムで**最大2段階**上がる。ただし**Sを超えない**。
  上がるまで育成開始をやり直せるので、**B以上なら実質Sスタートが可能**
- 逆に C・D は S に届きにくく、E 以下はほぼ届かない
- したがって **S・A・B の差は小さく、B と C の間が最大の崖**

### 発見：適性の合計はレア度で固定

較正に使った★5の5体は、G=0…S=7 で足した合計が地形 20〜21・間合い **20 で全員一致**。
★4のメレンゲは 18・16。**平均を取るとレア度しか出ず、体ごとの差は「配分」だけ。**
そのため評価は「B以上がいくつ・D以下がいくつ」を実質的に数える設計にした。

### 点数表と加重（`src/lib/monster-basics.js`）

| S | A | B | ‖ | C | ‖ | D | ‖ | E | F | G |
|---|---|---|---|---|---|---|---|---|---|---|
| 5.0 | 4.8 | 4.5 | | 3.0 | | 2.0 | | 1.0 | 0.6 | 0.3 |

高い順に並べて加重合計（ほぼ均等、上位にわずかに寄せる）。

- 間合い：0.30 / 0.28 / 0.24 / 0.18
- 地形：0.26 / 0.23 / 0.20 / 0.17 / 0.14

小数1桁に丸め、`n.n/5.0` と表示。**5.0 は全項目S（現状未到達）**。Sは既存最高のAより上に置いてあり
（S,A,B,D → 4.3、A,A,B,D → 4.2）、Sが将来出ても頭打ちにならない。

### 得意・苦手

- 得意 ＝ **B以上**（育成でSに届く）
- 苦手 ＝ **D以下**
- C はどちらでもない。複数該当は画面順で併記し、ランク文字も添える（森林B・火山A）

### 順位は出さない

「登録N体中M位」は初版で出していたが、母数が小さいうちは意味を持たないため撤去した（2026-09-17）。

### 較正表（2026-09-17・スクショ実測）

| モンスター | 地形 | 評価 | 得意 | 苦手 | 間合い | 評価 | 得意 | 苦手 |
|---|---|---:|---|---|---|---:|---|---|
| タマモノマエ 2690 | E B E B A | 3.5 | 森林・雪山・火山 | 砂漠・海岸 | D A A B | 4.2 | 中・近・零 | 遠 |
| ヴァナルガンド 0990 | D A D D A | 3.4 | 森林・火山 | 砂漠・海岸・雪山 | A C B B | 4.3 | 遠・近・零 | — |
| ティターニア 0190 | D B B B D | 3.7 | 森林・海岸・雪山 | 砂漠・火山 | A B B C | 4.3 | 遠・中・近 | — |
| フウマ 3490 | C A D D B | 3.5 | 森林・火山 | 海岸・雪山 | B B C A | 4.3 | 遠・中・零 | — |
| ワルキューレ 3290 | B D D B B | 3.7 | 砂漠・雪山・火山 | 森林・海岸 | B B B B | 4.5 | 全部 | — |

- 評価が同点でも得意・苦手の組み合わせは6体すべて異なる
- 較正の過程で却下した案：単純平均（合計固定で差が出ない）、上位加重だけ（ワルキューレと
  メレンゲの差が0.2しか出ない）、A>B の差を大きく取る（+2段階ルールに反する）

**式を変えるときは** `src/lib/monster-basics.js`、`scripts/test-monster-basics.js` の較正値、
`scripts/verify.js` 検査21の較正値、この表を同じPRで直し、`node build.js` で全ページを再生成する。

## 3. ページ上の出し方（`build.js` 5-11）

「評価解説」「おすすめ編成」の後、技セクションの前に `基礎データ` セクション。
ブロックは 素質 → 特徴 → 地形適性 → 間合い適性 の順で、**データがあるものだけ**出す。
PCでは素質6マス・特徴5マスをそれぞれ1行に収め、SP（480px以下）では素質を3列×2行、
特徴を「ガッツ回復力・移動速度」1行＋「成長タイプ・ヨイワル・サイズ」1行の2行にする。
1体も登録が無ければセクション自体を出さない。

各適性ブロックは、5（または4）マスのランク表 ＋ 評価・得意・苦手の3行。
末尾に「当サイト独自の指標」の注記1行（定型文はこの1行だけ）。

### 可視文字数への影響（実測）

| 入っている項目 | 増える可視文字数 |
|---|---:|
| 地形＋間合い | 約 +210字 |
| 素質＋特徴＋地形＋間合い | 約 +310字 |

**基礎データだけでは可視300字未満のページ（236件）は800字に届かない**（約200→510字）。
インデックス昇格には能力スコアリング（`docs/adsense-indexing-handoff.md` の1-c）が別途要る。
基礎データの役割は「1体ごとに違う内容を作る」ことで、字数は副次。

## 4. 運用

1. スキル `monster-basics-capture` でスクショ（1メッセージ10体まで）を読み、TSVへ転記
2. `node scripts/import-monster-basics-tsv.js` → FAIL 0
3. `node build.js` → `node scripts/test-monster-basics.js` → `node scripts/verify.js` FAIL 0
4. `CLAUDE.md`「現在の実数」を `build.js` ログの値へ更新してコミット
5. push・PR・マージは管理者の指示で

血統ごとに進める。358体 ÷ 10体 ≒ 36メッセージ。入った血統から詳細ページが厚くなる。
