# 技データ入力ガイド（スプレッドシート → JSON）

作成: 2026-09-03

技データはスプレッドシートで作り、TSVで書き出して取り込む。
CMS化（S3）のときも同じ列構成をシートのヘッダにするので、列名は変えないこと。

## 1. シートを作る

2枚のシートを用意する。テンプレートのヘッダ行をそのまま貼り付ける。

| シート | テンプレート |
|---|---|
| 技 | `src/data/_source/skills-template.tsv` |
| 技能力 | `src/data/_source/skill-abilities-template.tsv` |

バフ・デバフは血統をまたぐ共通の状態なので、血統ごとには作らない。
`src/data/_source/buffs.tsv` の1枚だけを全血統で共有する（列は `name` / `kind` /
`description` / `note` / `buffId`）。技能力への紐づけは取り込みが自動で行うので、
技能力シートに書く欄は無い。

**モンスターは名前で書く。**356体すべて名前が一意なので、4桁IDを調べる必要はない。
IDへの変換は取り込みスクリプトが行う。

## 1-2. スクリーンショットからの読み取りルール

「血統技図鑑」の画面から入力するときの対応表。**取り違えやすい点を先に潰しておく。**

| シートの列 | 画面のどこ | 注意 |
|---|---|---|
| `rank` | 技名の左の丸数字 | ①②③… がそのままランク |
| `range` | 技名の右のバッジ（遠／中／近／零） | 「移動間合い」の左側とも一致する |
| `aura` | **技名の左の色丸** | **丸が無い＝`無`オーラ。銀色の丸は`白`オーラ。**ここは間違えやすい |
| `moveTo` | 「移動間合い」 | `遠→零` なら `零`。**「なし」と表示されていたら空欄** |
| `ability1〜4` | 「技効果」欄 | モンスター詳細では「技能力」という名前だが同じもの。左上→右下の順に入れる |
| `abilityNUnlock` | 技能力をタップ →「解放条件」 | 「オロチの潜在能力を★★★★★に強化」→ `オロチ:10`。**ピンクの星は数＋5**（ピンク3つ＝★8） |
| `unlockedBy` | 「技登録条件」＋「登録可能なモンスター」 | 条件1の★の数がレアリティ。登録可能なモンスター全員に同じ★数を付ける |

**解放済みの技能力には解放条件が表示されない。**グレーアウトしている未解放のものだけ条件が読める。
読めなかった組は `abilityNUnlock` を空欄にしておくと、取り込み時に「解放条件が未入力」として
一覧で出るので、あとから埋める。可能なら**まだ解放していない状態で図鑑を開く**と手入力が減る。

**同じ名前の技能力は同一のものとして扱う。**`テクニックレイズ` のように複数の技に付く能力でも、
技能力シートには1行だけ書く。効果テキストは技によらず同じという前提で、
もし食い違ったら取り込みがエラーで止まる（そのときは設計を見直す合図）。
**解放条件は技ごとに違う**ので、能力ではなく技シートの `abilityNUnlock` 側に書く。

**候補はその血統の所属モンスターに限られるので
`monster/<4桁ID>.<拡張子>` と見比べて特定する。読み取った名前は必ず明示して、
入力者の確認を取ること。ここだけは文字が読めないので、推測で埋めない。

`unique`（固有技）と `owners` はこの画面から判別できない。あとから入力する。

**画像は1技ずつ送る。**技詳細を1枚目、そのあと技能力を「技効果」欄の左上→右下の順で並べる。
技能力は最大4つなので1技あたり5枚前後、上限10枚。まとめて送られた場合も処理はするが、
**どの画像をどの技として読んだかを必ず書き戻して確認を取る。**

## 2. 技シートの列

| 列 | 必須 | 内容 |
|---|:---:|---|
| `blood` | ● | 血統名。`キュービ` など。34血統のいずれか |
| `range` | ● | 技を**発動できる**間合い。`遠` `中` `近` `零` |
| `rank` | ● | 1〜6 |
| `name` | ● | 技名 |
| `aura` | ● | `赤` `青` `黄` `黒` `白` `緑` `無`。画面では丸なし＝`無`、銀色の丸＝`白` |
| `skillType` | ● | 技種。`ちから` `かしこさ` |
| `guts` | ● | 消費ガッツ。整数 |
| `moveTo` | | 発動後に移動する先。`遠→零` の `零` だけを書く。**画面が「なし」なら空欄** |
| `damage` | | `SS` 〜 `G`。各段に `+` 付きがある。不明なら空欄 |
| `accuracy` | | 命中率。同上 |
| `gutsDown` | | ガッツダウン。同上 |
| `critical` | | クリティカル率。同上 |
| `ability1`〜`ability4` | | 技能力の名前。技能力シートの `name` と一字一句そろえる |
| `ability1Unlock`〜`ability4Unlock` | | その技能力の解放条件。`モンスター名:★数`。条件が無い／読めない場合は空欄 |
| `unique` | | 固有技なら `1`。血統共通技は空欄 |
| `owners` | | 固有技のときだけ。使えるモンスター名を `・` 区切り |
| `unlockedBy` | | 技登録の解放元。`モンスター名:★数` を `,` 区切り。例 `セイラン:4,センリ:8`。空欄可（あとから足せる） |
| `note` | | 補足 |
| `skillId` | | **空欄でよい。**取り込み時に自動採番する |
| `version` | | **空欄でよい。**同名の出現順に自動で振られる（下の「6. 内容が変わったとき」） |

`moveTo` に `range` と同じ値を書くとエラーになる。移動しない技は空欄にすること。

同じ `blood` × `range` × `rank` に**血統共通技を2件**置くとエラーになる。1セル1技が原則で、
複数並ぶのは固有技がある場合だけ。

## 3. 技能力シートの列

| 列 | 必須 | 内容 |
|---|:---:|---|
| `name` | ● | 表示名。`狩の印Lv2` のようにLvも含めて書く |
| `description` | ● | 効果テキスト。改行は `\n`（半角バックスラッシュ + n）と書く |
| `tags` | | 分類。`,` 区切り |
| `abilityId` | | **空欄でよい。**自動採番する |
| `version` | | **空欄でよい。**同名の出現順に自動で振られる |

`baseName`（`狩の印`）と `level`（`2`）は `name` から自動で分解されるので入力しない。

同じ能力が複数の技に付く場合も、**技能力シートには1行だけ**書く。
技シート側は名前で参照する。内容が変わったときだけ行を足す（下の「6. 内容が変わったとき」）。

バフ・デバフ（`[霊魂]` `[火傷]` など）は**書かない。**説明テキストから自動で判定される。

## 4. 取り込む

```bash
node scripts/import-skills-tsv.js --dry
```

**引数は取らない。**技DBはまるごと書き直すので、`src/data/_source` の
`skills-<血統>.tsv` と `skill-abilities-<血統>.tsv` を毎回**全血統ぶん**読む
（1血統だけ渡すと他の血統が消えるため）。読んだファイルは実行時に一覧で出る。

`--dry` は書き込まずに検査だけする。エラーはファイル名と行番号つきで全件出るので、
シートを直してから `--dry` を外して実行する。

```bash
node scripts/import-skills-tsv.js
node build.js && node scripts/verify.js
```

`skillId` / `abilityId` は、既存DBに同じ技（血統＋技名）・同じ能力名があればそのIDを引き継ぐ。
IDは血統ページ内のアンカーなので、取り込みのたびに振り直さない。

## 5-2. 取り込みが出す報告

- **バージョン** — 同名が2行以上あると「技 キュービ種 八嵐天衝：v1 → v2（表示は v2）」と出る。
  意図的な操作なので確認は求められない。DBの版数よりTSVの行数が少ないと
  「取り込むと古い版が消えます」と警告が出るので、古い行を消していないか確かめる
- **バフ・デバフ** — どの技能力にどのバフが付いたかが一覧で出る
- **バフDB未登録の候補** — 角括弧にあるのに `buffs.tsv` に無い語。ゲーム内ヘルプの
  バフ・デバフなら `buffs.tsv` へ足して取り込み直す。発動条件（`[終盤]` `[有利]` など）なら
  `build.js` の `NON_BUFF_TOKENS` へ足す。**判断が付かなければ足さずに聞く**

## 6. 内容が変わったとき（バージョン）

ゲーム側のアップデートで技や技能力の内容が変わることがある。
**行を上書きすると元に戻せない**ので、同じ名前のまま新しい行を末尾に足す。
ページには最新版だけが出て、旧版はDBに残る。

| 状況 | やること |
|---|---|
| 転記ミスを見つけた | **その行を直す。**版は足さない |
| ゲーム側の更新で内容が変わった | **同じ名前のまま新しい行を追記する** |

`version` 列は空欄でよい。同じ名前が出てきた順に 1, 2, 3… が振られる。
**古い行は消さないこと。**隣り合う版の内容が完全に同じだと、
「更新でないなら版を足さずその行を直してください」とエラーになる。

## 7. 少しずつ入れてよい

技が1件でもある血統だけページが生成される。**分かる血統から順に入れられる。**
可視800字に届かないうちは `noindex,follow` になり、技が増えれば自動でインデックス対象へ昇格する。
