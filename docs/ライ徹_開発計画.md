# LINEモンスターファーム徹底攻略 開発計画

最終更新: 2026-08-23

## 1. 目的

現役運営者の独自コンテンツを守りながら、開発知識が少ない管理者でもClaudeへ依頼して、
通常ページの作業ブランチ作成、検証、PR、mainへのマージまで安全に進められる状態を維持する。

モンスターはGAS版ライ徹CMS、その他のページは通常の作業ブランチという管理境界を崩さない。

## 2. 文書の役割

| 文書 | 役割 |
|---|---|
| `AGENTS.md` | 短い恒久ルールと参照先。開発ルールの唯一の正 |
| `CLAUDE.md` | ガチャ、モンスター、カード、日記などのコンテンツ運用手順 |
| この文書 | 全体計画、段階、完了条件、当初計画からの変更 |
| `docs/PROGRESS.md` | 現在地、完了実績、次の作業、段階間の引き継ぎ |
| `docs/admin-development.md` | 管理者がClaudeへ依頼して開発・公開する具体手順 |

同じ手順を複数文書へ複製しない。恒久ルールは`AGENTS.md`、具体操作は参照先へ置く。

#### 1. リポジトリ内で実施する変更

##### R1 CMS公開Workflowのゲート強化

- 根拠: `.github/workflows/cms-publish.yml`
- 現状: `cms/publish`へのpushだけで起動し、同時実行は待ち行列、timeoutは10分、
  `permissions: contents: read`。Secretを`actions/checkout`の`token`へ渡すため、checkoutが
  保存した資格情報を最終`git push origin HEAD:main`も使用する。親コミットと`origin/main`の一致、
  ID生成、予測ID全件検算、build、verify、生成後の作業ツリー差分を順に検査し、失敗時は後続へ進まない。
- 危険性: `permissions`は`GITHUB_TOKEN`だけを制限し、`CMS_PUBLISH_TOKEN`自体の権限を狭めない。
  また現在の差分検査はbuild後の未コミット差分だけで、GASが作った元コミット`HEAD^..HEAD`の
  変更範囲を検査しない。Secretが侵害された場合、許可外ファイルを含む元コミットが検証を通る
  余地がある。最後のstep summaryはpush前に「completed」と書くため、push失敗時はrun結果を正とする。
- 本番影響: 現状監査は⚪。Workflow変更は将来のCMS公開を止めうるため🟡🔴
- 依存関係: R2、G1、H3。GASが正規に送る入力・画像の範囲を実物で確定してからallowlistを作る
- 復旧方法: test用ブランチで失敗時停止を確認し、問題時はWorkflow変更PRをrevertする。
  push前失敗なら`main`は不変で、管理画面から最新mainを基に再公開する
- 完了条件: 単一親、元コミット差分、生成差分、ID、build、verifyを独立ゲートにし、
  許可外変更を入れたテストがmain相当の対象を更新せずFAILする
