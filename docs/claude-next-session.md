## 現在地

- 第1段階は保留。ルール、管理境界、検証、PR・マージ手順は整備済み
- P10-1では作業ブランチ、push、PR、Actions成功、mainマージ、リモートブランチ削除まで確認済み
- 人工的な文書1行テストは省略し、第2段階の実更新で運用を確認する
- 第2段階はP11。具体的なタスクIDとブランチ名は更新内容を決めてから提示する
- GitHub Pagesはmain直接配信のため、通常PRのmainマージは即公開

## 変更先の境界

| 対象 | 更新方法 |
|---|---|
| モンスターの新規登録・属性・解説・編成・画像 | GAS版ライ徹CMSのみ |
| カード、日記、トップ、通常記事 | Claude＋通常の作業ブランチ |
| 生成HTML・sitemapの生成部分 | 正しい入力を変更して`build.js`で生成。手編集しない |

## 既知事項

- verifyには、348体時点の配列ロックと平文パスワード7ファイルについて既知WARNが出る
- 既知2件以外のWARNまたはFAILが増えた場合は停止する
- `cms/publish`はGAS専用。通常作業で使わない
- mainのブランチ保護はCMSの迂回経路を確認するまで有効化しない

## 第2段階の完了確認

- 実際に必要な更新が意図どおり反映された
- buildとverifyが成功した
- PR差分に対象外ファイルが無かった
- 管理者が公開タイミングを決めてmainへマージした
- PC幅とスマートフォン幅で対象ページを確認した
- 問題があれば`docs/PROGRESS.md`へ記録し、第1段階を必要な範囲だけ再開した
