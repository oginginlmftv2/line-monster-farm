## 1. 評価対象

- 能力は系列（I・II・III・IV）で来る。**I→II、III→IV は上位だけ**を評価する。
  **II と IV は別個体から得られるので並列**に評価する
- 序・破・急（古代トチカのちから、執事の心得）は別能力として3つとも評価する
- 下位段階は `superseded: true` を付けて評価とTierの母数から外す。解析はする（表示用に残す）
- 実測（2026-09-17）：1,248件中 評価対象 829件。うちカード日付あり 417件、直近1年 250件

## 2. 説明文の構造

説明文は `<br>` 区切りの行で、各行が「条件・トリガー → 効果」の形をしている。
語彙は有限で、パーサはこの表で読む。

### 2-1. 適用条件（hard）：誰が使えるか

角括弧 `[ ]` の自身属性。**カードTierにだけ効き、モンスターページの評価には効かない**
（そのモンスターが使えるかどうかを決めるだけ）。

| 形 | 例 |
|---|---|
| オーラ | `[自身赤]` `自身<オーラ緑>で` |
| モン類 | `[怪物]` |
| 血統 | `[主血統ガリ]` `[アーク種]` |
| または／かつ | `[自身赤または主血統ガリ]` `[青またはアーク種]` `[白または魔族]` |

### 2-2. 技条件（soft）：使う技の側の条件

`＜赤＞技発動時` のように**技の色・種類**にかかる条件。モンスターのオーラではない。
技DBがある血統は「その血統に赤技があるか」で判定でき、無い血統はオーラ一致で代用する（第2段）。

| 項目 | 例 |
|---|---|
| aura | `＜赤＞技` `＜オーラ黄＞技` `＜黒または無＞技` |
| stance | `＜オーラ有利＞技` `＜オーラ不利以外＞技` `＜オーラなし＞技` `オーラ技` |
| type | `＜ちから＞技` `かしこさ技` |
| rank | `R4以上の` |
| aptitude | `間合い適性S以上` `SS以上：` |
| range／position | `＜零距離＞技` `＜前衛＞技` |
| repeat | `1つ前と同じ技を使用したとき` |

### 2-3. 状況条件：いつ効くか（両方のTierに効く）

| 種別 | 語彙 |
|---|---|
| time | 序盤／前半／中盤／後半／終盤 |
| stance | 有利／有利以外／不利以外／自身有利／オーラ有利／モン類有利 |
| terrain | 砂漠／森林／海岸／雪山／火山（基礎データの地形適性と接続できる） |
| weather | 晴れ／曇り／悪天候 |
| position | 前衛／後衛／遠・中・近・零距離 |
| opponent | 相手黒／相手魔族／相手が＜オーラ緑＞のとき |
| state | 状態変化／怒 |
| compare | 相手より◯◯が高いと |
| life | ライフ50%未満／残りライフが少ないほど／ライフが100%の時 |
| probability | ＜40%＞の確率で／稀に |
| stack | スタック／回数に応じて／地形適性に応じて |
| while | この能力のシールド破壊まで／発動中 |
| numeric | 最大耐久値100／最大値+100（効果の上限。条件ではないが角括弧で来る） |
| size | 自身＜小さい＞で |

### 2-4. トリガー

技発動時／技命中時／技非命中時／被ダメ時／回避時／クリティカル時／バトル開始時／シールド破壊時

### 2-5. 効果原子（大分類6・中分類）

| 大分類 | 原子語 |
|---|---|
| 火力 | 与ダメ上昇／クリ率上昇／クリダメ上昇／クリ確定／追撃／連撃／攻撃ステ加算／技性能上昇／貫通／ステ上昇（ちから・かしこさ・攻撃ステ） |
| 命中 | 必中／命中率上昇／ステ上昇（命中） |
| 回避・防御 | 完全回避／回避率上昇／被ダメ低下／被ダメブロック／クリ無効／シールド展開／食いしばり／ステ上昇（回避・丈夫さ・ライフ） |
| ガッツ | ガッツ回復／ガッツダメ上昇／ガッツダメ低下／消費ガッツ |
| 弱体 | 相手ステ低下／相手被ダメ上昇／相手ガッツ停止／相手ガッツ減少／相手忠誠度減少／シールド破壊／封じ／デバフ付与 |
| 支援 | バフ付与／無効化・解除／オーラ変貌／適性効果上昇／ライフ回復／技ステ上昇／ステ変換 |

- **ステ上昇は「どのステが・何項目」で分ける**。`stats` を持ち、大分類は `STAT_CATEGORY` で決まる。
  全ステは6項目（「ライフを除く」なら5項目）として火力・命中・回避防御の全部に効く
- 数値は `value` と `unit`（`Lv`／`%`／`pt`／`large`＝「大上昇」）で持つ
- 角括弧で付与されるバフ（`[強撃Lv1]を付与` `[被ダメ-20%<20秒>]を付与`）は条件ではなく効果。
  中身を同じ原子語で解析し `granted: true` を付ける

### 2-6. 回数と秒数

| 表記 | 意味 | 持ち方 |
|---|---|---|
| **追撃・連撃に隣接する** `＜N回＞`（`＜1回＞追撃`／`追撃＜2回＞`／`追撃を＜1回＞与える`／`連撃Lv1×1回`） | **ヒット数**。トリガーごとに毎回 | `hits` |
| それ以外の `＜N回＞`（行末など） | **試合中の発動回数制限** | `limit` |
| `何回でも`／`各オーラ種毎に1回` | 制限なし／種別ごと | `limit: 'unlimited'` ／ `{per, n}` |
| `＜最大N回＞` `累積N回まで` | 上限・スタック | `maxStack` |
| `＜N秒＞`／`＜永続＞` | 継続 | `duration` |

ヒット数は数値係数に掛ける（10%×2回＝20%）。回数制限は補正で割り引く。
「追撃を＜1回＞与える」がヒット数であることは管理者確認済み（2026-09-17）。

## 3. 評価（第2段。値は3-1）

```text
行の評価   = base[原子語] × valueScale(数値) × statCount(項目数) × hits × Π modifiers(条件・トリガー・回数・秒数)
能力の評価 = 行の合計（同じ原子語は逓減）
power      = 能力の評価。手入力は ability-overrides.json の上書きだけ
```

- **適用条件（hard）は power に織り込まない。**カードTierの側で「使える体の割合」として掛ける
- 状況条件・技条件・トリガー・回数・秒数は power に織り込む（そのモンスターにとっても効く場面が限られるため）

```text
能力Tier（モンスターページ）  = 現役プール内の power の相対位置
カードTier（アシストカード）  = 現役プール内の power × 適用範囲 の相対位置
```

- Tierは1本。分類ごとに分けない。分類は表の列として見せる
- ~~現役プール＝カード日付が直近N か月~~ → 使わない（3-1「Tierと掲載範囲」）
- 新しい強い能力には大きい値が自動で付き、Tier境界が上がる。旧能力の値は触らない
- モンスターページは評価順の表（能力名・分類・条件・入手カード）。Tierは公開しない（3-1「Tierと掲載範囲」）。
  1本の総合点にはしない。表の形は描画PR（build-spec 5-12）で決める

基準値・係数を決めるときは、具体的な対（「必中Lv2＜1回＞ vs 与ダメ上昇Lv7」など）を並べて決め、
`ability-rubric.json` と本章を同じPRで更新する。

### 3-1. 種類ごとの検証記録（第2段）

能力の種類を1つずつ、ゲーム内ヘルプのキャプチャと管理者の確認で読みを決める。
**物差しは「与ダメ上昇Lv1＝1点」**。%表記はLvへ換算してから同じ物差しに載せる。

#### ダメージ上昇系（2026-09-26・ヘルプ「与ダメージ・被ダメージ」「特殊与ダメージ上昇」と管理者確認）

- **与ダメ上昇は1Lv＝1.8%**。`与ダメ上昇+10%` は Lv5.6 相当で、%表記の能力はLv表記より強いことが多い
- 被ダメ上昇（相手に付与するデバフ）も同じ定義で、1Lv＝1.8%
- 無印の与ダメージは**通常ダメージだけ**に効く。特殊与ダメは**通常・追撃・連撃**に効く

| 系統 | 表記 | 読み |
|---|---|---|
| A 与ダメ上昇 | `与ダメ上昇Lv3` `与ダメージ上昇Lv6` | 物差し。通常ダメージのみ |
| B 次の技だけ | `次の技の与ダメージ上昇Lv6` | Aと同じ値で、1発だけの補正を掛けるのでAより弱い |
| C 技ダメージ上昇 | `技ダメージ上昇Lv3` | **Aと同じ** |
| D 特殊与ダメ | `特殊与ダメ上昇Lv2` `特殊与ダメ<+10%>` | 追撃・連撃にも効くので同じLvならAより強い。Lvが低ければ当然弱い |
| E 与ダメの%表記 | `与ダメ上昇<+20%>` `与ダメ上昇+4%` | Aと同じ定義で %÷1.8 をLvとする |
| F 追撃だけ | `追撃与ダメ<+25%>` | 追撃は「メインダメの数%」なので同じ%でもAより弱く見える。ただし連撃が多く付く場合や、メインダメを軽減する効果に対しては強い |
| G 攻撃ステータス上昇 | `攻撃ステータス<10%>上昇` | ちから技・かしこさ技のどちらでも、**技が参照する側のステータス**にそのまま%分上乗せ |
| J 相手の被ダメ上昇 | `相手の被ダメ上昇Lv5` `相手に被ダメ上昇8%` | 1Lv＝1.8%（Aと同じ定義） |
| L 自分の被ダメ上昇 | `被ダメージ上昇<最大40%>` | デメリット。プラスに数えない |

決めた係数：

- B 次の技だけ：回数制限なしで命中ごとに付くものは ×0.5、`<1回>` は ×1/6（試合中の技6回を仮定）
- D 特殊与ダメ：Aの ×1.2（追撃・連撃を総ダメージの約2割と仮定）
- F 追撃だけ：同じ%のAの ×0.25。連撃が多い体・メインダメ軽減への強さは式では拾わない（割り切り）
- G 攻撃ステータス上昇：ダメージは攻撃ステータスにほぼ比例し、「与ダメの◯%で追撃」も一緒に伸びるので
  **Dと同じ扱い**。`攻撃ステータス+X%` ＝ X÷1.8 Lv × 1.2
- H 他ステを攻撃ステータスに加算：加算元（丈夫さ・回避・命中・かしこさ）は主力の攻撃ステータスと
  **同じ値（10割）とみなす**。`丈夫さのX%を加算` ＝ Gの `+X%` と同じ

#### 追撃・連撃（2026-09-26・管理者確認）

| 系統 | 表記 | 読み | 換算 |
|---|---|---|---|
| P 与ダメ参照の追撃 | `与ダメージの<10%>で追撃<1回>` | 与ダメ+X%とほぼ同じ | X÷1.8 Lv |
| Q ステ参照の追撃 | `ちからの10%の追撃ダメージ` `ライフの5%で追撃` | ステ値×X%の**完全固定ダメージ**。ちから1500なら150。メインダメ2000〜3000に対して5〜7.5%程度だが、相手の丈夫さに左右されずクリティカルも乗る | Pの ×0.7 |
| R 連撃 | `連撃Lv1×1回` | **連撃Lv1＝メインダメの10%**。回数分ヒット | Lv×10÷1.8 Lv ×ヒット数 |

- `＜回数＞` の付かない追撃（`かしこさ<10%>で追撃`）は**技が命中するたびに毎回出る**
- `＜1回＞` 等が追撃・連撃に隣接する場合は4章の確定どおりトリガーごとのヒット数

#### 命中・回避（2026-09-26・ヘルプ「必中と完全回避」と管理者確認）

- **命中率上昇は仮に1Lv＝1.8%**（与ダメと同じ。暫定）
- **基本の命中率は60%と仮定**（実際はステータス差による）。命中率+Xは期待ダメージを X÷60 倍だけ増やすので、
  `命中率+X%` ＝ (X÷60×100)÷1.8 Lv。`命中率+30%` は期待ダメージ+50%で Lv27.8。**命中率そのものの加算は強力**
- 命中率上昇Lv1（1.8%）は期待ダメージ+3%で、与ダメLv1.67相当
- 命中・回避ステータスの上昇は「お互い1500」を基準にステータス差で見る（係数はこれから決める）
- **必中と完全回避は、ほかの種類の能力と比べてもかなり強い**
- ヘルプ「必中と完全回避」：必中は発動中の技が必ず命中、完全回避は発動中の相手の技を必ず回避。
  同時に発動したらLvの高い方だけが効き、低い方は打ち消される。**必中は奇数Lv・完全回避は偶数Lv固定**なので
  同じLvでぶつかることは無い。Lvは強さではなく「ぶつかった時の勝ち負け」を決める

**命中・回避が重い理由（ガッツ）**：技の発動時にガッツを消費し、モーション中（数秒〜長いと6秒）は
自分のガッツが回復せず、相手のガッツは回復する。避けられるとダメージが0になるだけでなく、
ガッツ差が開いて相手の反撃機会が増え、消費ガッツによっては次の技までガッツを貯め直す必要が出る。
ダメージとガッツダメージは**技の発動時に計算**され、ガッツダメージはモーション開始と同時に減るが
モーション中に回復されてしまう。それでも「当てれば確定でガッツを減らせる」ことが重要。
したがって**1発の命中/非命中の差は、ダメージ分だけで見た値より大きい**（命中の価値倍率 M を掛ける）。

**必中・完全回避は常時の命中率・回避率より強い（揺るがない）**：ダメージがインフレした環境で
「2発当てたら勝てる」駆け引きになっており、1発を確定で当てる・確定で避ける利点が大きい。
確率を上げる常時効果とは別枠で、必中・完全回避1回には確定の価値を直接与える。

決めた値（2026-09-26）：

- 命中率・回避率の常時効果は **M＝1.5**（2026-09-27に3から下げた。インテンシブエンジン II の命中上昇Lv5が強すぎたため）。
  `命中率+X%` ＝ (X÷60×100)÷1.8 × M Lv（`命中率+30%` ＝ Lv41.7、命中率上昇Lv5 ＝ Lv12.5）
- **必中1回 ＝ Lv125**（M＝3のときの命中率+30%の1.5倍で決めた値。Mを下げても据え置き）。
  **完全回避1回は必中の1.5倍**（2026-09-27。1回あたりでも順位でも完全回避の方が強い）
- Lv補正：Lvごとに+20%（Lv1 ×1.0、Lv2 ×1.2、Lv3 ×1.4、Lv4 ×1.6）。完全回避Lv2＜1回＞ ＝ 125×1.5×1.2 ＝ Lv225
- 回数：`<1回>` は1回分、「発動技と次の技が必中」は2回分。回数の付かないもの（毎回）は**3回分で頭打ち**
  （2発で決着する環境なので3発目以降の価値は小さい）

#### 回避・防御（2026-09-26・ヘルプ「シールド」「ブロック」と管理者確認）

- **被ダメ低下も1Lv＝1.8%で、同じ%なら与ダメ上昇と同じ価値（攻守対称）**
- **被ダメ低下はメインダメしか軽減しない。連撃ダメージまで減らせるのはブロックだけ**
- 回避率上昇は命中率と対にして **M＝1.5**（2026-09-27に3から下げた）
- **被ダメカット** `最大ライフ20%以上の被ダメをカット` は、1発で受けるダメージを最大ライフの20%までに抑える。
  2発で決着する環境では「その1発で倒されない」に近く、**かなり強い**
- **食いしばり** `ライフ1で耐える<1回>` は**ほぼ完全回避1回（Lv125）**。
  超根性（状態変化・残りライフ少・稀に）は体感で**50〜70%発動**するので弱くない。`稀に` は0.6とする
- **ステ上昇はお互い1500を基準に見る**。`+3%` ＝ +45 なので `+100`（＝+6.7%）の方が強く、`+400`（＝+26.7%）は相当強い。
  ptは ÷1500 で%に直してから扱う
- ヘルプ「ブロック」：**通常・追撃・連撃ダメージ**に被ダメージ増減を適用する（被ダメ低下の特殊版。与ダメ側のDと対）
- ヘルプ「シールド」：展開中は受けるダメージを代わりに受ける。代わりに受けられる量＝**耐久値**で、
  特別な効果が無い限り**最大耐久値を超えない**。**最大耐久値は能力による展開で350、技発動時の展開で200**。
  複数発動したら1つずつ展開され、古いものが壊れてから効果時間内の新しいものが展開される
  （受けきれなかった分はライフへ）。効果時間は発動時から数える。
  **ギガシールド**は能力解除で打ち消されない（ほかはシールドと同じ、同時展開不可）。

#### Tierと掲載範囲（2026-09-27・管理者判断）

  少ない側は50%以下0.25・30%以下0.15・10%以下0.05。2発で決着する環境では「少ない」側は発動前に倒れることがある
- **「、さらに」の後ろは別の効果**として行を分ける。後ろの行は前の行のトリガー・条件を引き継ぐが、
  後ろに書かれた条件（`または相手[創造]時` など）は前の効果にかからない（リッピーカット II）
- `連撃ダメージ無効` `追撃／連撃ダメージをすべて無効化` は追撃・連撃の無効
- **技DBのある体は、技の色の条件をその色の技の割合で割り引く**（下限0.2）。技DBの無い体は平均の0.5

#### 未決

- 命中・回避・丈夫さステータスの上昇が、命中率・被ダメにどれだけ効くか（お互い1500を基準）
- 弱気の中身（保留）

#### パーサの直し（語彙の追加で済む）

- ダメージ上昇系：Dの「特殊」とFの「追撃だけ」をAと区別する／E・F・Jの%表記を拾う
- デメリットを符号付きで読む：自分の被ダメ上昇（L）、`回避率1%減少`、`ガッツ消費量10%上昇`、超逆上の `回避低下`
- `技発動時の命中率<20%>毎に…追撃`（カルキノスチェイサー）の命中率は効果ではなく条件
- `暗闘` を `暗闇` として読む

## 5. 運用：能力の追加と再評価

### 5-1. CMSで能力が増えたとき（順位が動くとき）

CMSのアシスト公開は `build.js` を回すので、**`src/data/ability-scores.json` は自動で作り直され、Tier境界も動く**。
新しい強い能力が入れば境界が上がり、旧能力の値は変わらない（インフレ対策）。
ただし**新しい能力の読み方は誰も確かめていない**ので、次の順で点検する。

1. `node build.js` のログに「未点検の能力 N件」が出る（`ability-rubric.json` の `review.reviewedThroughAbilityId` より後のID）
2. `node scripts/audit-ability-reading.js --new` で、新しい能力だけを読み違いの型ごとに点検する
3. 引っかかった型は3-1のルールで直す。語彙はパーサ、値は rubric、式は ability-score.js。
   直したら `node scripts/build-ability-parse.js`（カバレッジ表）→ `node build.js` → `node scripts/audit-ability-reading.js`（全体）
4. 新しい能力の点・順位を管理者に見せ、違和感が無ければ `review.reviewedThroughAbilityId` を最後のIDに進める
5. `scripts/test-ability-parser.js`・`scripts/test-ability-score.js`・`scripts/verify.js` がFAIL 0

### 5-2. 読み違いの型（2026-09-27の仮ビルドで見つかったもの）

機械で拾えるのは「読み残し」と「型にはまった書き方」だけ。**読めているのに意味の取り方が違うもの**
（相手<オーラ緑>技を自分の技と読む等）は、上位の並びと体ごとのおすすめを人が見て見つける。
能力を足したら、少なくとも上位100位に入った新能力は説明文と点の内訳を並べて確かめる。

| 型 | 例 | 対処 |
|---|---|---|
| 条件のかかる範囲 | 「、さらに…または相手[創造]時」の条件が前の効果にかかる | 「さらに」で行を分け、前の条件だけ引き継ぐ |
| 付与の効き方 | 「次の効果付与<1回>」を1発だけと読む | 秒数の無い付与はずっと効く。<N回>は重ねがけ |
| 「AとB」の片方 | 「回避ステータスと丈夫さステータス」「クリ率とクリダメ」 | 正規化で2つの効果に分ける |
| 累積・上限 | 「<+10%><最大+40%>」「〜する度に」 | 上限の値で持ち、累積の割引を掛ける |
| 段階の書き分け | 「1回：/2回：/3回：」「S以上SS未満：」「1つ以上：」 | 回避回数は段ごとに割引、セット数は常に効く |
| デメリットの符号 | 自分の被ダメ上昇・回避率減少・消費ガッツ上昇 | 符号付きで引く（デメリットは逓減しない） |
| 自分と相手の取り違え | 相手<オーラ緑>技・相手[創造]・相手技命中時 | 相手の条件・被ダメ時として読む |
| 読み残し・既定値 | 「ガッツ<50>回復」「攻撃ステータス上昇+10%」が読めず既定値30% | 語彙を足す |
| 基礎データの使い方 | 間合い適性（開始時の値）で「Sが無いから外す」 | 外さず、S以上に届く見込みを掛ける |

### 5-3. モンスターページへの載せ方（描画PRで build-spec 5-12 にする）

- 載せるのは**アシストのイベントで獲得できる能力（source＝イベント）**。閃き・EXトレ・状態変化は載せない
- その体が使える能力だけ：適用条件（オーラ・モン類・主血統）、技条件（技DBがあれば技の色、無ければオーラ一致）
- **順位の番号は振らない。**「TOP5」のように並べると人によって評価に違和感が出るため、
  選んだ能力は**実装（カード発売）が新しい順**に並べる。点数とTierは選別にだけ使い、ページには出さない
- **載せるのは点の上位5件**（2026-09-27）。選んだ5件を発売が新しい順に並べ、番号は振らない。
  発売日の無い能力（カード未登録のイベント能力）は発売日のある能力の後ろに置く
- 見出しは「相性のいいアシスト能力」。各能力は能力名・入手カード（レアリティ・発売年月・カードページへのリンク）・分類・説明文の全文。
  試しのページで可視文字数は約+1,000字（タマモノマエ +1,044字・ラクシャーガ +976字、8件のとき）
- **この機会に詳細ページのセクションの並びを変える**（管理者指定 2026-09-27）：
  基礎データ → 適性データ → 固有技 → ◯◯種の技（血統ページへのリンク） → 相性のいいアシスト能力 → 評価解説 →
  おすすめ編成 → 同じ血統のモンスター → 関連リンク。一覧に無い「登場ガチャ」は仮に関連リンクの直前（描画PRで確認）
