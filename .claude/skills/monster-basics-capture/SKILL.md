# モンスター基礎データのスクショ取り込み

LINEモンスターファームの「モンスター詳細」画面右上のタブ3枚（基礎・特徴・適性）を読み、
`src/data/_source/monster-basics-<血統slug>.tsv` へ転記して `src/data/monster-basics.json` を作る。
Vision APIは使わず、**画像は自分で読む。**

仕様の正は `docs/monster-basics-design.md`（スキーマ・評価式・較正）。
**このファイルと食い違ったらそちらが正。**

```text
スクショをまとめて添付（1メッセージ 10体まで。1体あたり最大3枚）
  → 1体1行の読み取り表を書き戻す（下の形式）
  → 入力者が確認
  → src/data/_source/monster-basics-<血統slug>.tsv へ追記
  → node scripts/import-monster-basics-tsv.js   … FAIL 0 で monster-basics.json を書き直す
「ビルドして」
  → node build.js → node scripts/test-monster-basics.js → node scripts/verify.js（FAIL 0）
  → CLAUDE.md「現在の実数」を build.js のログの値へ更新 → コミット
「マージして」と言われたときだけ
  → push → PR → マージ
```

**push・PR・マージは指示があるまで行わない。**コミットまでが「ビルドして」の範囲。

## 進め方：1メッセージ＝最大10体

複数体を一度に読むと**A体の値をB体に書く**取り違えが最大の事故になる。
それを機械で止めるため、1体ごとに次の照合を必ず行う。

1. **本人確認。**画面左上のモンスター名を `src/data/monster-ids.json` の `name` で引き、
   `bloodSlug` からTSVのファイルを決める。**IDを推測しない。**名前が見つからなければその体は保留
2. **属性照合。**名前の左の色丸（オーラ）と「怪物」などのバッジ（モン類）を、
   `monster-ids.json` の `aura`・`mon` と見比べる。**違えばその体は書かずに報告**
   （別モンスターの画面を読んでいる、または既存データの誤り）
3. 3枚のうち**どの枚があるか**を確認する。無い枚の項目は空欄にする（あとから足せる）

11体以上添付されたら、先頭10体だけ処理して残りは次のメッセージへ回すと伝える。

## 画面は3枚

すべて「モンスター詳細」の右上。タブが「基礎」「特徴」「適性」の順に並ぶ。

### 1枚目：基礎タブ → 素質

| 画面 | 列 | 値 |
|---|---|---|
| 「素質」列（**右端**）の6行 | `life` `power` `wisdom` `accuracy` `evasion` `defense` | 符号付き整数％。`0%` `-5%` `+20%` |

行の並びは上から ライフ・ちから・かしこさ・命中・回避・丈夫さ。左のラベルと対応させる。

⚠️ **素質はレア度上げで入力者が割り振って強化できる個体値を含む。**画面の％は
「素の素質＋割り振り分」なので、入力者が「ライフを1振っている」などと申告したら、
その分を引いた素の値を書く。申告が無い場合は画面の値をそのまま書き、読み取り表に
「割り振り未確認」と添えて入力者に確認する。**推測で引かない。**

⚠️ **その左の `F` などの文字は読まない。**あれは現在の基礎ステータスに対するランクで、
育成状態によって変わる個体値。素質は％の列だけ。基礎ステータスの数値（106/950 など）も読まない。

### 2枚目：特徴タブ

| 画面 | 列 | 値 |
|---|---|---|
| ガッツ回復力 | `gutsRecovery` | `G`〜`S` |
| 移動速度 | `moveSpeed` | `G`〜`S` |
| 成長タイプ | `growthType` | 文字列（例 `ふつう`） |
| ヨイワル | `goodEvil` | 文字列（例 `ややヨイ`） |
| サイズ | `size` | 文字列（例 `小さい`） |

読まないもの：血統アイコン・忠誠度・人気度・才能・モン類（モン類は照合にだけ使う）。

成長タイプ・ヨイワル・サイズは `src/lib/monster-basics.js` の列挙で検査される。
**列挙に無い値が画面に出ていたら、その値を報告して列挙へ追加してから取り込む。**
推測で列挙を増やさない。

### 3枚目：適性タブ

| 画面 | 列 | 値 |
|---|---|---|
| 地形適性（砂漠・森林・海岸・雪山・火山） | `砂漠` `森林` `海岸` `雪山` `火山` | `G`〜`S` |
| 間合い適性（遠・中・近・零） | `遠` `中` `近` `零` | `G`〜`S` |

地形は2段組（上段：砂漠・森林・海岸、下段：雪山・火山）。ラベルと値を1組ずつ対応させる。
**適性に `+` は無い。**`B+` と読めたら読み間違いなので拡大して確認する。

## 読み取り表（書き戻す形式）

```text
| 名前 | ID | 血統 | 照合 | 素質(ライ/ち/か/命/回/丈) | ガッツ回復/移動 | 成長/ヨイワル/サイズ | 地形(砂/森/海/雪/火) | 間合い(遠/中/近/零) |
| メレンゲ | 3151 | ゴースト | 赤・怪物 ✔ | 0/-5/+10/+20/+5/-5 | A/B | ふつう/ややヨイ/小さい | C/F/D/B/B | B/D/B/D |
```

無い枚は `—`。照合が合わない体は「照合✘：画面は青・魔族、データは赤・怪物」と書いて保留する。

## ランク文字の見分け方

ランクは色付きの太字1文字。**B と D、E と F を最も間違えやすい。**

- 色で補助する：S/A 赤系、B ピンク、C 緑、D 水色、E 青、F 紫、G 茶。
  ただし色だけで決めず、必ず文字の形を見る
- 迷ったら拡大する

```bash
sips -g pixelWidth -g pixelHeight <画像>
sips -c 120 520 --cropOffset <y> <x> <画像> --out crop.png   # --cropOffset は y x の順
sips -z 360 1560 crop.png --out crop-big.png
```

拡大しても決めきれなければ、**書かずに入力者へ聞く。**推測で埋めない。

## TSVのルール

- ヘッダーは `src/data/_source/monster-basics-template.tsv` と完全一致
- 1体1行。同じモンスターが2行あると取り込みがFAILする
- 素質6項目・地形5項目・間合い4項目は**それぞれ全部埋めるか全部空**。一部だけ埋めるとFAIL
- 特徴タブの5項目は1つずつ任意
- `capturedAt` はスクショを撮った日（分からなければ取り込み日）を `YYYY-MM-DD`
- 行の血統がファイル名の血統と違うとFAILする（別血統のファイルへ書いた事故を止める）
- 値を直すときはTSVの行を直して取り込み直す。`monster-basics.json` は手で編集しない
  （TSVと一致しないと `verify.js` 検査21がFAILする）

## 評価値は書かない

地形評価・間合い評価・得意/苦手は `build.js` が `src/lib/monster-basics.js` の式で
毎回計算する。TSVにもJSONにも書かない。式を変えるときはそのファイルと
`scripts/test-monster-basics.js`・`docs/monster-basics-design.md` を一緒に直す。
