# アシスト能力のスクショ取り込み

LINEモンスターファームの能力のスクショを読み、CMS（ライ徹CMS）の能力DBへ入れるJSONを作る。
Vision APIは使わず、**画像は自分で読む。**設計は `docs/ability-capture-design.md`。

DBの正はCMSの `abilities` シート。`src/data/assist-abilities.json` はCMS公開で上書きされる写しなので、
**リポジトリのJSONは書き換えない。**このスキルの出力はCMSへ貼るJSONで、保存は入力者がCMSで行う。

```
スクショ（1カードぶん）＋カード名
  → 読取JSON（下の形式）を scratchpad に書く
  → node scripts/check-assist-ability-payload.js <読取JSON> --emit <貼り付け用JSON>
  → FAIL 0 なら判定表と貼り付け用JSONを渡す
  → 入力者が CMS のカード →「能力取り込み」タブに貼る →「判定を確認」→ 照合チェック → 保存
  → 能力タブで draft を確認済み（verified）にして、アシスト公開
```

参考の読取例: `examples/c0003-MR-hirameki.json`（アルカードの閃き8件）。

## 外部DB（lMfDB）との関係 — ここが要点

正は**スクショ**。lMfDB由来の既存能力とは、**カード＋能力名**で照合する（全角半角・ローマ数字・空白をそろえた比較用キー。保存値は変えない）。
検査スクリプトが1件ずつ判定する。自分で判定を書き換えない。

| 判定 | 意味 | CMSで起きること |
|---|---|---|
| `known` | このカードに同名・同文の能力が登録済み | 何もしない |
| `known_diff` | 同名は登録済みだが本文が違う（ゲーム側の文面改訂が多い） | 何もしない。**WARNの差分を入力者へ伝える。**移行データ（`legacyId`あり）は本文ロックなので直さない。それ以外はCMSの能力編集で直す |
| `link` | 未紐付け（unlinked/ambiguous）の既存能力に同名があり、元のカード名がこのカード | **新規を作らず**、既存の`abilityId`をこのカードへ紐付ける。lMfDBの履歴（`ability_external_refs`）とはabilityIdでつながったまま |
| `link_ambiguous` | 上の候補が複数 | FAIL。候補を入力者に見せ、選ばれた`abilityId`を`linkTo`に書いて再検査 |
| `create` | どれにも当たらない | 新規能力（draft）。abilityIdはサーバー採番 |

新規で作った能力は、次回のlMfDB監査で「同じカードに同名あり」（`local_card_name_match`）になり、
新規候補に二重に出ない。

**閃きの汎用名**（`[自身青]不屈`・`[雪山]防塵`など）は全カードで同じ名前なので、他カードの同名とは紐付けない
（検査も元のカード名が一致するものだけを候補にする）。

## 進め方：1カード＝1メッセージ

1. **カードを特定する。**
   - 閃きの「能力詳細」は、背景の「アシストカード詳細」上部にカード名が見える（例「アルカード」）
   - **イベントの「イベント詳細」にはカード名が出ない。**入力者のメッセージにカード名が無ければ、読む前に聞く
   - `src/data/assist-cards.json` の `name` + `rarity` から `cardId` を引く。同名が複数ならレアリティで絞り、決まらなければ聞く。**推測しない**
2. **能力を上から順に読む。**スクロール撮影で同じ能力が2枚に写ったら1件にまとめる。
   `I` と `II` は別の能力なので潰さない
3. 読取JSONを書き、検査を通す（FAILは直して再実行）
4. **判定表を全件書き戻す。**能力名／source／判定／abilityId の4列。`known_diff`と`link`の本文差分（WARN）は本文に全部書く
5. 貼り付け用JSONを本文にコードブロックで全文出す（入力者がそこからコピーする）

## 画面の読み方

### 閃き能力（アシストカード詳細 → 能力をタップ →「能力詳細」）

- 1枚に能力1件。枠の1行目が**能力名**（例 `[自身青]不屈`、`[火山]ちから＋１００`）、下線の下が**本文**
- `source` は `閃き`
- 下の「必要能力Pt」とアイコンは保存しない

### イベント能力（イベント →「イベント詳細」→「能力」）

- 1つのイベントに能力枠が並ぶ（青枠がⅠ、オレンジ枠がⅡのことが多い。**枠の色は保存しない**）
- 枠の1行目が能力名（例 `光香む常闇の衣Ⅰ`）、点線の下が本文
- `source` は `イベント`（画面下の「※能力はひらめきで獲得します」は獲得方法の説明で、sourceではない）
- 右の「必要能力Pt」とアイコンは保存しない

### 本文の改行

画面の折り返し（枠幅での改行）は**改行ではない。**`ライフ／ステ`のように単語の途中でも折り返す。
次のときだけ `<br>` を入れる。

- 行頭が `・` で始まる（箇条書き）
- 前の文が終わり、条件の角括弧から新しい文が始まる（閃きの `[自身青][終盤]…カットする` の次の `[自身青][終盤]…無効＜１回＞`）

`・` も条件の角括弧も無い継続行（例 `[最大値＋２００]` が単独で次行に来た場合）は、前の行へつなぐ。

## 表記の変換（画面 → DBの規約）

既存1,248件の実測に合わせる。検査がFAILで落とすので、書く前に合わせる。

| 画面 | DB | 例 |
|---|---|---|
| 角括弧 `［前半］` | **半角** `[前半]` | `[前半][自身青]` |
| 山括弧 `<1回>` `＜２０秒＞` | **全角** `＜＞` | `＜１回＞` |
| 本文の数字・％・＋・－ | **全角** | `＜－１５％＞`、`ライフ３０％未満時`、`ちからステータス＋１００` |
| 本文の例外（半角のまま） | `Lv1`、`R4`、`[最大2回まで]` | 既存DBがこの形 |
| 墨付き括弧 `【シールド】` | そのまま | 前後の空白は詰める |
| スラッシュ `/` | そのまま半角 | `連撃/追撃` |
| 名前のローマ数字 `Ⅰ` `Ⅱ` | **半角英字＋前に半角空白** | `光香む常闇の衣 I`（**効果スキルとは逆**） |
| 名前の数字・＋ | **全角** | `[火山]ちから＋１００` |
| 名前の `%` | 既存の表記に合わせる（多くは半角） | `[自身青]ちから＋３%` |
| 行頭の `・` | `<br>・` | `…＜１回＞<br>・相手の攻撃ステ＜－１５％＞` |

**既存DBに同じ名前（比較用キーが同じ）があれば、その表記に合わせる。**違えば検査がFAILで既存の表記を示す。

## 読取JSONの形

```json
{
  "cardId": "c0003-MR",
  "sourceScreenshots": ["IMG_0001.png"],
  "abilities": [
    {
      "name": "[自身青]不屈",
      "description": "[自身青][終盤]ライフ３０％未満時、最大ライフ２０％以上の被ダメージをカットする<br>[自身青][終盤]ライフ３０％未満時、連撃/追撃を無効＜１回＞",
      "source": "閃き",
      "tags": ["オーラ青"]
    }
  ]
}
```

- `abilityId`・`sortOrder`・`rarity`・`sourceName` は書かない（rarityとsourceNameはカードから、IDと並びはサーバーが決める）
- `tags` は任意の**提案**。CMSのタグ候補か既存DBにある語だけ使える。**同じ名前の既存能力のタグ**を第一候補にし、
  無ければアイコン（盾→`シールド`、拳＋上矢印→`攻撃強化`）と `[自身青]`→`オーラ青`・`[幻霊]`→`幻霊` 程度にとどめる。迷ったら空配列
- `linkTo` は `link_ambiguous` で入力者が選んだ `abilityId` だけ書く
- 1回30件まで

## 検査と出力

```bash
node scripts/check-assist-ability-payload.js <読取JSON> --emit <貼り付け用JSON>
```

- **FAIL** は直してから再実行。FAILを残したまま貼り付け用JSONを渡さない
- **WARN** は本文に全部書く（本文差分・半角数字）
- **INFO「近い既存名」**は誤字か新しい能力かを見分ける。`[晴れ]` と `[曇り]` のような別条件は新規で正しい
- 貼り付け用JSONは判定（`action`）付き。CMSはサーバーで判定し直し、食い違えば保存を拒否する
  （検査後に誰かがCMSで能力を足した場合など）。そのときは検査からやり直す

## CMSでの保存（入力者が行う）

1. CMSで対象カードを開き、「能力取り込み」タブ
2. 貼り付けて「判定を確認（読み取りのみ）」。サーバー判定が一覧に出る
3. 原画像と見比べ、「原画像と全件を照合した」にチェック → 保存
4. 能力タブで draft の能力を確認し、確認済み（verified）にして「変更を保存」
5. アシスト公開（draftの能力はカードページに出ない）

## 絶対に守ること

- **読めない値は推測しない。**潰れて読めない能力はJSONから外し、本文で「能力N（〜）が読めない」と報告する
- **カードが分からなければ読まない。**イベント詳細にはカード名が出ない
- **既存DBの本文に合わせて書き換えない。**スクショの文面が正。表記（全角半角・括弧）だけを規約に合わせる
- **判定を手で変えない。**`link` を `create` にしたい（別の能力だと分かっている）場合は入力者に確認し、その理由を本文に書く
- **リポジトリのDB（`src/data/assist-abilities.json`）は編集しない**
- **CMSの保存は入力者が行う。**Claude in Chrome で代行する場合も、保存ボタンの前に必ず確認を取る
- 1メッセージ＝1カード。複数カードが混ざっていたら、どの画像をどのカードとして読んだか宣言する
