# モンスター技のスクショ取り込み

LINEモンスターファームの技データを、ゲーム画面のスクリーンショットから
`src/data/_source/skills-<血統slug>.tsv` へ転記し、技DBへ取り込む。

仕様の正は `docs/skill-input-guide.md`（列とルール）と `docs/build-spec.md` 5-9/5-10（表示）。
**このファイルと食い違ったらそちらが正。**

## 進め方：1技につき2ステップ

**1メッセージ＝1技。**技能力の名前は複数の技に出てくるため、まとめて処理すると
どの技の解放条件なのか取り違える。ステップごとに読み取り結果を全部書き戻して確認を取る。

| | 送られるもの |
|---|---|
| ステップ1 | 技の基本画面（下記AまたはB） |
| ステップ2 | 技能力の詳細。技効果欄の**左上→右下の順** |

ステップ1を受けたら読み取り結果を表で返し、ステップ2を待つ。
ステップ2が揃ってからTSVへ書き、取り込む。

## 画面は2種類ある

### A. 血統技図鑑（血統共通技）

ステップ1は2枚。

1. **図鑑トップ** — 技登録条件の★の数と、登録可能なモンスター（画像のみ）
2. **技詳細** — 技種／移動間合い／消費ガッツ／4評価／技効果の一覧

`unique` は空欄、`owners` は空欄。`unlockedBy` は図鑑トップから読む。

### B. モンスター詳細の技タブ（専用技＝固有技）

**専用技は血統技図鑑に載らない**ので、モンスター詳細画面のキャプチャで来る。
1画面に技グリッドと選択中の技の詳細が両方写っている。ステップ1は1枚。

- 画面上部にモンスター名がある → `owners` にその名前
- `unique` は `1`
- `blood` は `src/data/monster-ids.json` でそのモンスターから引く（推測しない）
- `unlockedBy` は**空欄**（登録条件が無い）
- ⚠️ **技タブには専用技と血統共通技が両方並ぶ。**この画面だけでは区別できない。
  **名前では判断できない。**「八嵐天衝」「神域移動」のような凝った名前の共通技もあれば、
  「警戒」のような汎用的な名前の専用技もある。技グリッドの中身もモンスターごとに違うので
  図鑑と見比べても分からない。
  唯一confidentに言えるのは「狐火・藍」「提灯落とし・炎」のような
  **登録済みの共通技名＋接尾辞**の形のときだけ。**それ以外は必ず入力者に聞く。**
  共通技だった場合は図鑑側のキャプチャ（★と登録可能モンスター）が別途必要
- ランクは技名の左の丸数字
- **間合いは技グリッドの「列」で決まる。**左から 遠・中・近・零 の4列で、
  選択中（黄枠）の技がどの列にあるかを見る。
  **グリッド上部の 遠中近零 は常に4つとも点灯している列見出しで、選択状態ではない。**
  「今どのタブが選ばれているか」で読むと間違える
- 「連動能力」は記録しない（DBに列が無い）

## 読み取り表

| 列 | 画面のどこ | 注意 |
|---|---|---|
| `rank` | 技名の左の丸数字 | ①②③… がそのままランク |
| `range` | 技名の右のバッジ／「移動間合い」の左側 | 遠・中・近・零 |
| `aura` | **技名の左の色丸** | 最も間違えやすい。下の「オーラ色の見分け方」を必ず読む |
| `skillType` | 技種 | ちから／かしこさ |
| `guts` | 消費ガッツ | |
| `moveTo` | 「移動間合い」 | `遠→零` なら `零`。**「なし」なら空欄** |
| `damage` `accuracy` `gutsDown` `critical` | 4つの評価 | `S+`〜`G`。各段に `+` 付きがある |
| `ability1`〜`4` | 「技効果」欄 | 左上→右下の順。モンスター詳細では「技能力」と呼ばれるが同じ |
| `abilityN` の効果テキスト | 技能力をタップした「能力詳細」 | 改行は `\n` と書く |
| `abilityNUnlock` | 「技能力詳細」の解放条件 | 「オロチの潜在能力を★★★★★に強化」→ `オロチ:10` |
| `unlockedBy` | 「技登録条件」＋「登録可能なモンスター」 | 条件1の★の数。登録可能なモンスター全員に同じ★数 |

### オーラ色の見分け方

**赤・青・緑・黄はそのまま。迷うのは無彩色の3つで、ここが最頻の誤読。**

| 見た目 | `aura` |
|---|---|
| 丸が無い | `無` |
| **暗い銀（ガンメタル／濃いグレー。中の紋章がうっすら見える程度）** | **`黒`** |
| **明るい白銀（ほぼ白く光る）** | **`白`** |

暗い銀を `白` と読むのが典型的な失敗。**濃いグレーに見えたら `黒`。**

見比べの基準として、登録済みの2件が使える。
**キュービ種「狐火」＝`白`（明るい白銀、紋章が白く光る）／「王狐焔」＝`黒`（暗いガンメタル）。**
判断に迷ったら、この2つのどちらに近いかで決める。

丸は小さく、縮小された画像では色が潰れる。**無彩色に見えた時点で必ず拡大して確認する。**

```bash
sips -g pixelWidth -g pixelHeight <画像>   # 実寸を出す（表示座標と倍率が違う）
sips -c 90 300 --cropOffset <y> <x> <画像> --out crop.png
sips -z 270 900 crop.png --out crop-big.png  # 3倍に拡大してから読む
```

`--cropOffset` は **y x の順**。技名バーは画面右ペインの上端にあるので、
表示座標に `実寸幅 ÷ 表示幅` を掛けてから指定する。

拡大しても**白か黒か決めきれなければ、書かずに入力者へ聞く。**推測で埋めない。

### ★の数え方

技登録も技能力の解放も**同じ1〜10の尺度**。白星は数そのまま、**ピンク星は数＋5**
（ピンク3つ＝★8、ピンク5つ＝★10）。

### 解放条件の有無

**解放条件が無い技能力のほうが多い。空欄が既定。**

- グレーアウト（未解放）の技能力 → タップすると解放条件が出る → そのまま書く
- 通常表示（解放済み）の技能力 → 条件があっても表示されない
  - 条件が無さそうなら空欄
  - **条件がありそうだが読めない場合だけ `?`** と書く。取り込みは通り、手入力待ちとして報告される

### 同じ名前の技能力

**同じ内容の能力なら、技能力シートには1行だけ書く。**複数の技に付いても行は増やさない。
**解放条件だけは技ごとに違う**ので、技シートの `abilityNUnlock` 側に書く。

内容が変わったときだけ行を足す。次の「バージョン」を読むこと。

## バージョン：内容が変わったら上書きしない

技も技能力も、ゲーム側のアップデートで内容が変わる。**上書きすると戻せない**ので、
同じ名前のまま新しい行を足して版を積む。**ページに出るのは最新版だけ**で、
旧版はロールバック用にDBへ残る。

| 状況 | やること |
|---|---|
| 転記ミスを見つけた | **その行を直す。**版は足さない |
| ゲーム側の更新で内容が変わった | **同じ名前のまま新しい行を末尾に追記する** |

`version` 列は**空欄でよい。**同じ名前がTSVに出てきた順に 1, 2, 3… が自動で振られるので、
末尾に足すだけで新しい版になる。取り込みは
「技 キュービ種 八嵐天衝：v1 → v2（表示は v2）」と報告する。
**同じ技を入れ直している時点で意図的なので、確認は求めない。**

古い行は消さないこと。TSVの行数がDBの版数より少ないと、取り込みが
「取り込むと古い版が消えます」と警告する。

## バフ・デバフ

`[霊魂]` `[火傷Lv1＜20秒＞]` のような角括弧はゲーム内ヘルプに定義がある共通の状態で、
`src/data/_source/buffs.tsv` に一覧がある。**転記も入力もしなくてよい。**
取り込みが技能力テキストから自動で結び、ページでは技能力カードの中に説明が出る。

取り込みが**「バフDB未登録の候補」**を出したら、その場で確認する。

- ゲーム内ヘルプの「バフ」「デバフ」にある語 → `src/data/_source/buffs.tsv` へ1行足して取り込み直す
- 発動条件やゲーム用語（`[終盤]` `[有利]` など） → `build.js` の `NON_BUFF_TOKENS` へ足す

**どちらか分からなければ入力者に聞く。**推測でバフDBへ足さない。

## モンスターの特定

「登録可能なモンスター」と、専用技の所有者は**画像だけで名前が出ない。**

1. その血統の所属モンスターを `src/data/monster-ids.json` から絞る（14体前後になる）
2. `monster/<4桁ID>.<拡張子>` を Read して見比べる
3. **読み取った名前を必ず本文に書いて確認を取る。**推測で埋めない

モンスター名は356体すべて一意なので、TSVには名前で書く。IDへの変換は取り込みが行う。

## 出力と取り込み

血統ごとに2ファイル。無ければヘッダ行から作る（`src/data/_source/skills-template.tsv` を複製）。

```
src/data/_source/skills-<血統slug>.tsv
src/data/_source/skill-abilities-<血統slug>.tsv
```

血統slugは `monster-ids.json` の `bloodSlug`（キュービ→kyubi）。

既存ファイルへは**追記**する。転記ミスの訂正はその行を書き換え、
ゲーム側の更新は新しい行を追記する（上の「バージョン」を参照）。

```bash
node scripts/import-skills-tsv.js src/data/_source/skills-<slug>.tsv src/data/_source/skill-abilities-<slug>.tsv --dry
```

`--dry` で検査だけ通してから、外して本実行。そのあと必ず両方を通す。

```bash
node build.js && node scripts/verify.js
```

`verify.js` が FAIL 0 でなければ、原因を報告して止まる。**FAILを残したまま次の技へ進まない。**

## 絶対に守ること

- **読み取れない値は推測しない。**空欄にして「この値が読めなかった」と報告する。
  攻略情報なので、埋まっているように見えて実は捏造、が最悪の結果になる
- **読み取り結果を毎回すべて書き戻す。**表で返し、確認を取ってから次へ進む
- **モンスターは読み取った名前を明示する**
- 1メッセージ＝1技。まとめて送られた場合も処理はするが、
  **どの画像をどの技として読んだかを必ず宣言する**
- **CSS・レイアウト・色・余白は範囲外。**ブラウザでの見た目確認もしない
  （`build.js` と `verify.js` が通ればよい）。気づいても**報告だけして直さない。**
  技の登録中にCSSを触ると、どの変更がどの技のせいか追えなくなる
- **文言はその場で直してよい。**転記したテキストの表記ゆれ（全角と半角、記号の統一）、
  `note`、`build.js` が出すラベルや導入文など。**1件ずつ直すほうが、
  あとでまとめて見直すより手間が少ない。**
  ただし `build.js` のテンプレートを触ると**全血統のページに効く**ので、
  何をどう変えたかを報告すること

## 注意：公開が始まる閾値

技が数件入ると血統ページが可視800字を超え、**noindexが外れて sitemap に載る。**
`node build.js` のログに字数が出るので、800字を超えたら報告する。
GitHub Pages は `main` を直接配信するため、マージ＝本番公開になる。
