# GASコードの貼り付け用ページ

`_cms/gas/` の変更はリポジトリにマージされただけでは本番CMSに反映されない。管理者がApps Script
エディタへ同名ファイルの内容を貼り直し、新バージョンでデプロイして初めて動く。この受け渡しは
毎回同じ形にする。提示方法が回ごとに変わると管理者が迷い、ターミナルへ貼ったコードは
コピー時に欠けやすく、ファイル送付は「どれを貼るのか」が分からなくなった実績がある。

```
対象ファイルを決める（マージ済みPRの _cms/gas/ 差分）
  → git fetch origin
  → node scripts/gas-handoff.js <ファイル名>... --out <scratchpad>/gas-handoff
  → 1ファイルにつき1つ Artifact で公開（favicon 📋）
  → リンクと「貼る順番・デプロイ・確認方法」を短く渡す
```

## 1. 対象ファイルを決める

原則は **マージ済みPRで変わった `_cms/gas/` のファイル全部**。1つでも漏れると、UIが呼ぶAPIが
サーバーに無い（またはその逆）状態になる。差分は次で取る。

```bash
git fetch origin && git diff --name-only <マージ前のmain>..origin/main -- _cms/gas/
```

`manifest.json` と `README.md` は貼る対象ではない（GASエディタに同名ファイルが無い）。
複数PRぶんまとめて渡すときも、ファイル単位で最新の `origin/main` を渡せばよい。

## 2. 生成する

```bash
node scripts/gas-handoff.js 22_assist_status.gs ui_assist.html --out <scratchpad>/gas-handoff
```

- 既定で **`origin/main` の内容**を読む（`git show`）。作業ツリーは別セッションの未コミット変更を
  含みうるので使わない。未マージのブランチを渡したいときだけ `--ref <branch>`、
  作業ツリーを渡したいときだけ `--worktree`
- 出力は1ファイル1HTML。コードは隠した `<pre>` に持ち「全文をコピー」ボタンで
  クリップボードへ渡す。可視 `<pre>` に全文を出すと `ui_assist.html`（130KB超）で
  ページが開けなくなる
- 照合用に行数・文字数・1行目・最終行・SHA-256、貼り付け手順、`api_` 関数の一覧と
  コンソール確認行（`Object.keys(google.script.run).filter(k=>k.startsWith('api_'))`）を載せる

生成されたHTMLは中身を書き換えない。載せる情報を変えたいならスクリプト側を直す。

## 3. 公開する

1ファイルにつき1回 `Artifact` で公開する。`favicon` は `📋`、`description` は
「本番GASの <ファイル名> へ貼るコピペ用ページ（<タスクID> <一言>）」。
同じファイルを後日また渡すときは新しいArtifactでよい（内容が違うので）。

## 4. 渡し方

リンクを表にして、次だけ添える。長い説明は要らない（ページ内に手順がある）。

| ファイル | 貼る先 | リンク |
|---|---|---|
| `22_assist_status.gs` | スクリプト「22_assist_status」 | <URL> |
| `ui_assist.html` | HTML「ui_assist」 | <URL> |

- **全ファイルを貼り終えてから**「デプロイ → デプロイを管理 → 編集 → 新バージョン → デプロイ」。
  途中で保存するだけでは本番は変わらない
- 反映確認: 管理画面を開き直してコンソールで `api_` 一覧を見るか、対象機能を1回試す
- 反映後にやる運用作業（例: エイルの能力を紐付け解除→再紐付け→公開）があれば1〜3行で

## やらないこと

- コードをターミナル本文へ貼る、`SendUserFile` でファイルだけ送る、手順だけ文章で書く
- 作業ツリーの内容を無確認で渡す（ローカルmainが遅れていた事故あり。`origin/main` を正とする）
- Apps Scriptエディタ・デプロイ・スプレッドシートを自分で操作する（管理者作業）
