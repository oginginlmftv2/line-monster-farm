# アシスト効果のスクショ取り込み

LINEモンスターファームの「アシストカード詳細 → アシスト効果」タブのスクショを読み、
CMS（ライ徹CMS）の効果DBへ入れるためのJSONを作る。Vision APIは使わず、**画像は自分で読む。**

DBの正は CMS の `assist_effects` シート。`src/data/assist-effects.json` はCMS公開で
上書きされる生成物なので、**リポジトリのJSONは書き換えない。**このスキルの出力はCMSへ貼る
JSONであり、保存は入力者がCMSで行う。

```
スクショ（1カードぶん、上から下まで）
  → 読取JSON（下の形式）を scratchpad に書く
  → node scripts/check-assist-effect-payload.js <読取JSON> --emit <貼り付け用JSON>
  → FAIL 0 なら貼り付け用JSONを渡す
  → 入力者が CMS「効果OCR」タブ → 「候補JSONを貼り付け」→ 原画像確認 → 効果編集へ反映 → 保存
```

参考の読取例: `examples/c20k-MR-teosu.json`（テオス、スクショ4枚・効果12件）。

## 進め方：1カード＝1メッセージ

1. **カードを特定する。**画面上部のカード名（例「テオス」）とレアリティバッジ（MR/SSR）を読み、
   `src/data/assist-cards.json` の `name` + `rarity` から `cardId` を引く。**推測しない。**
   同名が複数あればレアリティで絞り、それでも決まらなければ入力者に聞く
2. **効果を上から順に読む。**スクロール撮影なので画像同士が重なる。**同じ効果が2枚に写る**ので、
   効果名＋説明で同一と判断して1件にする。**同名で数値だけ違う効果**（トレ効果アップ +10% と +8%、
   忠誠度効果アップ +25% と +20%）は**別の効果**なので潰さない
3. 読取JSONを書き、検査を通す
4. **読み取り結果を表で全部書き戻す。**効果名／解放ランク／限定／条件 の4列。入力者の確認を待たずに
   貼り付け用JSONまで出してよいが、WARNは必ず本文に書く

画面の最下部（最後の効果の下に余白があり、スクロールバーが下端）まで写っていなければ
**撮り漏れの可能性を報告する。**最後の効果は4凸のことが多い。

## 読み取り表

| 列 | 画面のどこ | 注意 |
|---|---|---|
| `name` | 各効果枠の1行目（太字） | 先頭の **✿ は書かない**（限定の印。`conditional` で表す） |
| `description` | 効果名の下の本文 | 画面の改行位置ではなく**文の切れ目で `\n`**。下の「説明文の改行」を読む |
| `unlockRank` | 効果名の右の**コイン4枚** | 青（水色）の数。0=無凸 1=1凸 2=2凸 3=3凸 4=4凸 |
| `conditional` | 効果枠の**背景色** | 薄いオレンジ（黄）= `1`、白= `0` |
| `conditions` | 説明文の「〜が一致したとき」 | `conditional=1` のときだけ。下の「条件の起こし方」 |

### 解放ランク（コイン）

効果名の右に丸いコインが4枚ある。**左から順に青く点灯**し、青の枚数が解放段階。
灰色（茶系）は未点灯。**枚数ではなく色を数える**（4枚あるのは常に同じ）。

- 4枚とも灰色 → `無凸`
- 左1枚だけ青 → `1凸` … 4枚とも青 → `4凸`

画面は**無凸→4凸の順**に並ぶ。読み取った並びでランクが下がっていたら、検査がFAILにする。
その場合はコインの色を拡大して読み直す。

```bash
sips -g pixelWidth -g pixelHeight <画像>
sips -c 60 260 --cropOffset <y> <x> <画像> --out coins.png   # --cropOffset は y x の順
sips -z 180 780 coins.png --out coins-big.png
```

### 限定（背景色）と ✿

一致時限定の効果は、効果枠の背景が**薄いオレンジ**で、効果名の先頭に **✿** が付くことが多い。
ただし**✿が無くても背景が黄色なら限定**（テオスの「血統オーラ上限解放 +60」は✿なしで黄）。
**背景色で決め、✿は補助**にする。迷ったら拡大して白い枠と見比べる。

### 条件の起こし方

`conditional=1` の効果は、説明文の「〜が一致したとき」から条件種別を選ぶ。

| 説明文 | `types` |
|---|---|
| 主血統 | `mainBloodlineMatch` |
| 副血統 | `subBloodlineMatch` |
| オーラ | `auraMatch` |
| モン類 | `monTypeMatch` |
| 種族 | `speciesMatch` |

- 「主血統、副血統またはオーラが一致したとき」 → `{"operator":"or","types":["mainBloodlineMatch","subBloodlineMatch","auraMatch"]}`
- 1種類だけ → `{"operator":"and","types":["monTypeMatch"]}`（1件のときは `and`）
- **「モン類ブリーダー・鍛錬」「モン類ブリーダー・継承」「オーラブリーダー・〜」**のように
  説明文に「一致したとき」が無い派生効果は、**名前のブリーダー種別**で決める
  （モン類ブリーダー系 → `monTypeMatch`、オーラブリーダー系 → `auraMatch`）
- 「かつ」「すべて」なら `and`。「または」「いずれか」なら `or`。両方混ざっていたら入力者に聞く

条件の原文は保存しない（DBに列が無い）。

## 表記規約

検査（`check-assist-effect-payload.js`）が機械的に落とすので、書く前に合わせる。

| 項目 | 規約 | 例 |
|---|---|---|
| 効果名の数値 | `+` の**直前に半角スペース1個**、`+` の後は詰める | `トレ効果アップ +10%`、`アサルト上限アップ +120` |
| 効果名のローマ数字 | 全角 `Ⅱ Ⅲ` を**名前に直付け**（空白なし） | `アサルトボーナスⅡ +1` |
| 説明文の `+` | **前後に空白なし** | `ブリーダートレ出現率+15%` |
| 括弧 | 全角 `（ ）` | `（最大3人まで）（重複不可）` |
| 読点 | `、` の後に空白を入れない | |
| 数値なしの効果名 | そのまま。末尾に `+` を付けない | `モン類ブリーダー・鍛錬` |
| スラッシュ | 画面どおり半角 `/` | `オーラブリーダー/モン類ブリーダー` |

### 説明文の改行

画面の折り返し（枠幅による改行）は**改行ではない。**次のときだけ `\n` を入れる。

- 文が終わって次の文が始まる（画面上でも行頭が揃って新しい文になっている）
- 「ブリーダートレ出現率+15%」「ちから、かしこさの素質アップ+1%」のような**箇条書き的な短文**の区切り

`（最大10%）（重複不可）` のような括弧の連続は同じ文なので改行しない。
句点 `。` は画面に無ければ書かない。

## 読取JSONの形

```json
{
  "cardId": "c20k-MR-teosu",
  "sourceScreenshots": ["IMG_0001.png", "IMG_0002.png"],
  "effects": [
    {
      "name": "モン類ブリーダー +60%",
      "description": "育成対象とモン類が一致したとき、ブリーダーがトレーニングに出現する（最大3人まで）",
      "unlockRank": "無凸",
      "conditional": 1,
      "conditions": { "operator": "and", "types": ["monTypeMatch"] }
    },
    {
      "name": "トレ効果アップ +10%",
      "description": "一緒にトレーニングしたとき、基礎ステータスの上昇量アップ",
      "unlockRank": "無凸",
      "conditional": 0,
      "conditions": null
    }
  ]
}
```

`effectId` と `sortOrder` は書かない（CMSが採番・並び順から付ける）。
`sourceScreenshots` には添付された画像のファイル名を入れる（CMSの候補に「元画像」として出る）。

## 検査と出力

```bash
node scripts/check-assist-effect-payload.js <読取JSON> --emit <貼り付け用JSON>
```

- **FAIL** は直してから再実行。FAILを残したまま貼り付け用JSONを渡さない
- **WARN** は本文に全部書く。とくに次の2つは入力者の判断が要る
  - 「同名の既存効果と説明が違う」 → 今回のスクショの文面が正なら、そのまま進めてよい。
    既存側が誤読（`ブルーダー` など）ならその旨を伝える。**既存カードのDBは直さない**（別作業）
  - 「既存効果 N 件が消える」 → 登録済みカードを撮り直した場合に出る。撮り漏れでないか確認する
- **INFO の「DB初出の効果名。近い既存名: …」**は、誤字か新しい数値かを見分ける。
  `+100` と `+120` のような数値違いは新規で正しい。文字違いなら読み直す

貼り付け用JSONは scratchpad に書き、**本文にもコードブロックで全文を出す**（入力者がそこからコピーする）。

## CMSでの保存（入力者が行う）

1. CMSで対象カードを開き、「効果OCR」タブ
2. 「候補JSONを貼り付け」に貼り、「貼り付けたJSONを候補にする」
3. 候補を原画像と見比べ、「原画像確認」にチェック → 「効果編集へ反映（未保存）」
4. 「効果」タブで確認 → 「効果を保存」

CMSは `cardId` が表示中のカードと違えば拒否する。保存すると `verified` になり、
次回の CMS公開（`cms/assist-publish`）で `assist-effects.json` と `cards/card.html` へ反映される。

## 絶対に守ること

- **読み取れない値は推測しない。**数値が潰れて読めない効果は、その効果を `"name": "?"` にせず
  **JSONから外して本文で「効果N（〜）が読めない」と報告する。**攻略情報なので捏造が最悪
- **コインと背景色は必ず拡大して確認する。**縮小画像では青と灰、白と薄オレンジが潰れる
- **既存DBの説明に合わせて書き換えない。**スクショの文面が正。既存との差は検査がWARNで出す
- **リポジトリのDB（`src/data/assist-effects.json`）は編集しない。**CMS公開で上書きされる
- **CMSの保存は入力者が行う。**Claude in Chrome で代行する場合も、「効果を保存」を押す前に必ず確認を取る
- 1メッセージ＝1カード。複数カードが混ざっていたら、どの画像をどのカードとして読んだか宣言する
