# プレイ日記の執筆

管理人ぎんの一人称で、1記事＝1ページの日記を書く。反映手順の正は `CLAUDE.md` の「プレイ日記追加時の注意」。
文体の見本は次の2本。書く前に必ず本文を読む。

- `diary/mr-rival-julia-ikusei.html`（育成日記。解説寄り）
- `diary/lol-chou-choujou-yuushou.html`（大会結果。配信の発言を地の文にした例）

## 進め方（3段階・各段階で止まって確認）

1. **構成案**：見出しごとに入れる内容を箇条書きで出す。入れない話題（配信の脱線など）も明示する。
   不明点（発言の意図、個体名、画像掲載可否）は推測で埋めず質問にまとめる
2. **本文案**：チャットに全文を出す。ページはまだ作らない
3. **ページ化**：OKが出てから HTML 作成と反映。コミット・PR・マージは指示があったときだけ

## 文体

- です・ます調の口語。一人称は「**俺**」（「僕」「私」にしない）
- 結論を先に。導入1〜2文で何があったかを言い切る
- 1段落3〜5文。見出しは短い名詞句（「エントリーした個体」「今日から大イベント祭」）
- 口癖を自然に混ぜる：「正直」「めちゃくちゃ」「なんやかんや」「〜と思います」「〜んですよね」
- 自虐・ツッコミ・オチを入れてよい。区切りのオチに「以上です。」を使う（記事末尾でなく途中でもよい）
- 締めはみんなに向けた前向きな一言（「これからもみんなで一緒にライモンを楽しみましょう！」系）
- 大会結果の記事は冒頭と締めで投票・応援へのお礼を言う

### 配信の文字起こしを使うとき

- 「配信でこう言っていました」と**報告しない**。その場で話しているように地の文へ置く
- ただし口語そのままは強すぎるので**文章用にマイルドに**する（「〜だろ」「おい」→「〜ですよね」、断定を和らげる）
- 文字起こしの誤変換はゲーム用語に直す（例：原霊→幻霊、ローマス＝ロードオブマスターズ）
- 挨拶・視聴者の名前・記事テーマと無関係な脱線は入れない
- マニアックな用語（「4フォイブリチェ」など）はユーザーがOKならそのまま使う
- 事実（日付・順位・個体名・数値）は発言やスクショにあるものだけ。推測で足さない

## ページ化

`diary/mr-rival-julia-ikusei.html` をひな形にする（head・header・footer・CSSを流用）。

- スラッグは英字ローマ字（例 `lol-chou-choujou-yuushou`）。title・description・canonical・h1をユニークに
- タグ：育成＝`tag-solo`「⭐ 育成日記」、ローマス／ローレジェ＝`tag-lomas`「👑 …」、グラスラ＝`tag-gurasura`。
  使うタグのCSSを記事側 `<style>` にも入れる
- 画像は `diary-img/<スラッグ>.jpg` 等に置き、`diary-img-single`（縦長スクショ）か `diary-img-wide` で載せる
- byline は `著者：<a href="../profile.html">ぎん</a> ／ YYYY年M月D日 公開`

続けて `CLAUDE.md`「プレイ日記追加時の注意」の手順を全部行う：

1. 前の記事の `diary-nav` に「次の記事 ›」を追加
2. `diary.html` 先頭にカード（日付・タグ・タイトル・抜粋）
3. 本文が可視800字以上なら `sitemap.xml` に追加し、`build.js` の `existingBlocks.length !== N` と
   `CLAUDE.md` の「現在の実数」「最終更新」、`docs/admin-development.md` の同じ数値を更新。
   800字未満なら `noindex,follow` を付けてsitemapに載せない
4. `index.html` の日記プレビューを最新4件に入れ替え
5. `index.html` の更新履歴へ追記。**`// GACHA:UPDATES:START`〜`END` の内側には入れない**（`END` の直後に置く）
6. 大会実績なら `profile.html` の実績サマリー・実績セクションも更新するか確認する
7. `node build.js` → `node scripts/verify.js` が FAIL 0
